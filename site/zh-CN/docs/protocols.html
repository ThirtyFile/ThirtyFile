SFTP、S3 和 FTP

程序可通过标准协议操作 ThirtyFile 文件。管理员启用后即可使用 SFTP。S3 存储桶和 FTP 接收文件夹是独立功能，提供状态如下说明。

如何选择

使用 WebDAV 将空间挂载为磁盘；使用 SFTP 通过 WinSCP、FileZilla、Cyberduck、OpenSSH 或 rclone 进行加密传输。SFTP 显示与 WebDAV 相同的目录树，遵循相同权限。

SFTP

在控制台 › 常规 › 应用程序与协议开启允许 SFTP 访问，默认关闭。启动时使用 THIRTYFILE_SFTP_ADDR 设置端口（默认 0.0.0.0:2022）。在 Docker Compose 单独发布端口，SFTP 不经过 HTTP 反向代理。

services:
  thirtyfile:
    environment:
      THIRTYFILE_SFTP_ADDR: 0.0.0.0:2022
    ports:
      - "8080:8080"
      - "2022:2022"

将这些项目加入现有 Compose 服务，保留镜像和卷。使用 docker compose up -d 重新启动，仅在必要的网络范围开放所选 TCP 端口。

连接

在客户端选择 SFTP，输入服务器主机名、端口 2022、ThirtyFile 用户名和应用程序密码。此处不接受账号密码。只读应用程序密码无法修改文件，管理员也一样。第一次信任连接前，请核对控制台显示的主机密钥指纹。

sftp -P 2022 amy@files.example.com
# After connecting:
ls
cd "My files"
put report.csv
get report.csv

SSH 公钥

管理员也须开启允许 SSH 密钥。在账号菜单 › SFTP 密钥添加名称和 SSH 公钥，按要求确认当前密码和双因素验证码。私钥请保留在自己的设备。对话框显示指纹和上次使用时间，移除密钥后会停止访问，包括现有连接。

sftp -i ~/.ssh/id_ed25519 -P 2022 amy@files.example.com

SFTP 支持范围

访问权限由 ThirtyFile 角色和共享设置控制。Unix 所有者变更会被拒绝。权限变更（例如 chmod 600 和 scp -p）会被接受但不改变任何内容。客户端设置的修改时间（rclone、WinSCP、scp -p）会与文件内容一起保存并再次显示，因此按大小和时间同步时只会传送有更改的文件；从其他地方更改内容后，会显示在 ThirtyFile 中更改的时间。S3 报告的也是同一个时间。使用 rclone 时请设置 disable_hashcheck = true，因为服务器不提供计算远程校验和的 Shell 命令。若无法访问控制台，请向管理员获取预期的主机密钥指纹。

可列出和下载文件、上传、从指定位置续传、创建文件夹、重命名、移动及移除项目（送到回收站）。写入先暂存，关闭文件时才提交，并应用配额、上传限制、版本及活动记录。断线时丢弃未完成写入。接受客户端时间设置但不保存。不提供 Shell、命令执行、SSH rsync、转发或符号链接。每个账号最多五个连接，每个连接最多 32 个打开项目，闲置五分钟后超时。

首次启动时，服务器在数据目录生成 ed25519 主机密钥，请一起备份。更换密钥会改变指纹，客户端应要求你重新确认。

S3 存储桶

将团队或公司文件夹发布为存储桶。每个 Access Key 只能访问该文件夹，并按创建者当前的权限操作。这与将现有 S3 服务添加为存储位置不同。

端点设置

在控制面板 › 常规 › 应用程序与协议 › S3 启用 S3，输入独立主机名，例如 s3.files.example.com，并选择区域（默认 us-east-1）。S3 默认关闭。代理将此主机名转发至与网站相同的 HTTP 端口，无需新增 Docker 端口。请保留原始 Host 请求头，它是签名的一部分。S3 主机名需要有效的 HTTPS 证书和 DNS 记录。

将以下指令加入 S3 主机名的 HTTPS server 配置块，沿用现有证书设置。请按磁盘容量和空间配额设置适当的上传限制。

location / {
    proxy_pass http://thirtyfile:8080;
    proxy_set_header Host $http_host;
    proxy_request_buffering off;
    proxy_buffering off;
    client_max_body_size 0;
}

发布和密钥

右键点击文件夹并选择发布为 S3 存储桶…，或打开属性 › S3 存储桶。名称必须唯一，由 3–63 个小写字母、数字和连字符组成。重命名或移动文件夹不会改变存储桶名称。

管理员可发布团队或公司文件夹。空间管理者还须有账号的分享权限，并启用允许空间管理者发布存储桶。个人空间及可创建分享链接的人设为无人的空间不能发布。文件夹在回收站内、创建者失去管理权限或空间停用时，存储桶会停止。还原文件夹或访问权限后，已启用的存储桶会恢复工作。

发布存储桶和创建密钥时，会要求输入你当前的密码；开启了两步验证时还要输入验证码。密钥以发布存储桶的人的身份运行，所以只有发布者或管理员可以创建它的密钥，或重新启用已停止的存储桶或密钥；其他管理这个文件夹的人可以停止或删除它们。每项更改都会记录在活动日志中。

创建一个或多个密钥，填写说明、只读或读写访问权限和可选的到期日。请立即保存 Secret Key，它只显示一次。密钥使用数据目录的 secret.key 加密，请按备份指南保存该文件。已启用密钥到期前三天内，创建者会收到访问权限即将结束的通知。只读空间只能创建只读密钥；创建者的账号不能更改文件时，其存储桶也只能创建只读密钥，因为读写密钥以创建者的身份运作。

可单独停用或删除密钥，不影响其他密钥。控制面板 › S3 存储桶 列出所有存储桶、创建者、密钥和上次使用时间。停用存储桶会阻止全部密钥；删除存储桶或密钥不会删除文件。Access Keys 不能登录网站、SFTP 或 WebDAV。活动记录会标明存储桶和密钥说明，不会记录凭据。

客户端

在程序中选择 S3 兼容服务：端点 https://s3.files.example.com、区域 us-east-1（或自行设置的区域）、路径样式 URL 和存储桶密钥。不要启用虚拟托管样式 URL、ACL 或服务器端加密设置。

使用 aws cli 时，请交互设置命名配置文件，避免机密出现在命令历史中。将寻址方式设为 path，并在每条命令指定端点。

aws configure --profile thirtyfile
aws configure set s3.addressing_style path --profile thirtyfile
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 ls s3://backups/
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 cp report.csv s3://backups/report.csv

使用 rclone 时运行 rclone config，选择 S3、提供商 Other，交互输入密钥，设置端点和区域，启用 force_path_style，并将 ACL 和服务器端加密留空。rclone copy 可增加文件；rclone sync 可能移除目标文件。

ThirtyFile 会将 rclone 的 x-amz-meta-mtime 与当前内容版本一起保存，也支持使用同名复制更新时间。其他自定义元数据（例如 rclone 为大型上传加上的 MD5）会被接受但不保存。no_system_metadata 无法阻止 rclone 发送此时间戳，请保持关闭。这不会改变 S3 以外的文件修改时间。

备份和其他用途

使用 restic 时，将备份文件夹发布为 backups，并创建读写密钥。从受保护的凭据存储区加载 AWS_ACCESS_KEY_ID 和 AWS_SECRET_ACCESS_KEY。Repository 密码与 S3 密钥不同，请妥善保管。只在专用的空文件夹中初始化。

restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path init
restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path backup ./documents

Duplicati 或 Synology Hyper Backup 可使用 S3 兼容目标，设置相同端点、区域和路径样式 URL。请勿在浏览器中编辑备份 repository 文件。此 S3 端点是这些工具的目标，与 ThirtyFile 自身的备份和副本策略不同。

合作伙伴读取价目表时，可将价目表文件夹发布为 price-lists，并创建 90 天后到期的只读密钥。数据团队应为每个 rclone 或 aws cli 任务创建独立密钥，便于分别停用。

文件夹映射和限制

a/b/c.txt 等 key 对应嵌套文件夹和文件；PUT 会创建缺少的父文件夹。以 / 结尾的空对象代表文件夹。列表使用 UTF-8 字节排序、前缀、分隔符和有上限的分页。路径穿越、空路径组件、非法字符或前后空格的名称会被拒绝。不区分大小写的空间会拒绝仅大小写不同的名称冲突。

DELETE 会将文件和文件夹移至回收站。覆盖会按空间策略保留旧版本。空间配额和上传大小限制均适用。MD5 ETag 标识上传内容，服务器会验证 Content-MD5 和支持的 AWS 校验和请求头。分段上传的片段在临时存储区保留最多一天，可中止未完成上传以提前释放。每个密钥最多 32 个、每个存储桶最多 128 个待完成上传（全服务器 512 个），每次最多 10,000 个片段。

支持的操作包括 ListBuckets（仅该密钥的存储桶）、HeadBucket、GetBucketLocation、ListObjects/V2、HEAD、范围和条件式 GET、PUT、同一存储桶内的 COPY、DELETE 和批量删除、分段创建／上传／完成／中止／列出，以及预签名 GET/PUT。PUT 和完成分段上传支持 If-None-Match: *（仅在该 key 尚无对象时写入，Terraform 的锁定文件需要此功能）和 If-Match（仅覆盖该 ETag 的内容）；存储对象时会再次检查条件，因此两个同时写入者只有一个会成功。删除文件夹 key（以 / 结尾）时，只有空文件夹会被删除，如同 S3 只移除文件夹标记：其中的对象会保留。请求超过 1,000 个 key、分段或上传时，和 AWS 一样返回 1,000 个。预签名 URL 最长有效七天，密钥到期或停用后立即失效。只读密钥即使使用预签名 URL 也不能 PUT。没有另外要求时，下载是附件（Content-Disposition: attachment、X-Content-Type-Options: nosniff）。预签名 URL 可以像 S3 一样用 response-* 参数要求其他的显示方式、文件名、类型或缓存设置；这些参数属于签名的一部分，所以只有持有密钥的人能要求。

不提供 ACL、通过 S3 创建存储桶、存储桶策略、生命周期、Object Lock、S3 版本 API、对象标签、服务器端加密设置或虚拟托管样式 URL。不支持的操作返回 NotImplemented。时钟需与服务器相差 15 分钟以内；错误签名与登录共用失败限制。

FTP 接收文件夹

FTP 接收文件夹让扫描仪等设备使用专用凭据上传到单个文件夹。此功能默认关闭，与将现有 FTP 服务器添加为存储位置不同。设备不使用你的账号密码或应用程序密码。

启用 FTP 和显式 FTPS

在控制台 › 常规 › 应用程序与协议启用FTP 接收文件夹。挂载用户 1000 可读取的 PEM 证书链和私钥。在 Docker Compose 服务添加下列选项后重启：

services:
  thirtyfile:
    ports:
      - "2121:2121"
      - "30000-30009:30000-30009"
    volumes:
      - ./ftp-tls:/ftp-tls:ro
    environment:
      THIRTYFILE_FTP_ADDR: 0.0.0.0:2121
      THIRTYFILE_FTP_PASSIVE: 30000-30009
      THIRTYFILE_FTP_PASSIVE_HOST: ftp.files.example.com
      THIRTYFILE_FTP_CERT: /ftp-tls/fullchain.pem
      THIRTYFILE_FTP_KEY: /ftp-tls/privkey.pem

默认控制地址为 0.0.0.0:21，此示例使用 2121。控制端口和整个被动模式端口范围都要开放，内外端口号相同。NAT 需将这些端口转发至服务器，并将被动模式主机设为公网 DNS 名称或 IPv4 地址。FTP 不经过 HTTP 反向代理。请使用显式 FTPS（AUTH TLS）、验证服务器证书，并加密数据连接（PROT P）。不提供隐式 FTPS 或主动模式。

公网连接必须加密。只有可信局域网的旧设备，才由管理员允许直接连接的私有或本机地址使用明文 FTP；密码和文件会以明文发送。请将监听服务限制在可信局域网，不要通过 TCP 代理或互联网端口转发使用明文 FTP。反向代理请求头不会改变这项策略。未配置证书时，只接受明确允许的私有网络连接。控制台显示端口或证书错误并自动重试，不会阻止网站启动。FTP 关闭时不开放端口，也不读取证书。Docker 的端口代理永远不会被当成局域网设备：Docker 以这种方式转发公开的端口时，所有连接看起来都来自容器的网关，因此会拒绝明文 FTP。要让设备以自己的地址被识别，请让容器使用主机网络，或关闭 Docker 的 userland proxy。

为设备创建专用接收文件夹

右键点击文件夹选择创建 FTP 接收文件夹…，或从详细信息／属性打开。管理员可以发布团队文件夹，空间管理者需经 FTP 策略允许。个人空间、访客账号和关闭分享链接的空间不能发布。为每个设备设置易于辨认的名称和可选的到期日。请立即保存生成的设备用户名和密码；密码只显示一次。

设备设置使用被动模式、服务器主机名和控制端口、设备凭据，上传目录为 /。文件夹重命名或移动后，发布仍跟随其标识。默认允许上传；列出内容和下载是两个独立选项，默认均关闭，仅启用设备需要的权限。SIZE、MDTM 和文件元数据需要下载权限。设备不能删除、移动、重命名、更改权限或执行命令。请使用以 STOR 保存的设备；不支持续传、追加上传或“先上传临时名称再重命名”流程。默认情况下，上传会替换同名文件并保留先前版本，适合重复保存相同名称的摄像头。扫描仪请关闭替换同名文件，名称已被使用的新文件会加上编号，现有文件不会改变。

只有发布接收文件夹的人或管理员可以轮换它的密码、重新启用它、允许设备列出或下载文件，或延长它的到期日；其他管理这个文件夹的人可以停止、缩小权限或删除它。活动日志的每一条都会写出接收文件夹的名称。

控制台 › FTP 接收文件夹列出所有发布、创建者、目标文件夹、权限、到期日和上次使用时间。确认身份后可编辑停用、轮换密码或删除凭据。策略更改或密码轮换也会使现有连接失效；轮换后使用新密码重新连接，文件仍保留。到期、文件夹进入回收站、创建者被停用或失去发布权限、空间分享关闭时，访问也会停止。上级发布不能穿越嵌套受限文件夹的边界，管理员也一样。

传输限制与记录

上传内容在提交前保持私密；失败或取消会清除临时内容并保留原文件。同名文件上传成功时，按空间版本策略保留先前版本。空间配额、只读空间和单文件上传限制仍适用。活动记录标明创建者和接收文件夹，不记录凭据。

每个接收文件夹最多同时 5 个连接，服务器最多 128 个控制连接。登录限时 30 秒，控制连接空闲 2 分钟、数据停滞 30 秒后结束，连接最长 1 小时。列表最多 10,000 项，建议设备使用较小的接收文件夹。错误密码共用网站的来源地址登录限制。被动数据连接的来源必须与控制连接相同，拒绝 FTP bounce／FXP 和符号链接。此功能供兼容设备收件使用，不是通用 FTP 账号。

使用案例

服务器可使用 SSH 密钥和 SFTP 脚本上传每晚报表；设计师可使用 Cyberduck 传输大型项目。使用 rclone 时执行 rclone config，选择 SFTP 并设置主机名和端口，核对主机密钥，使用应用程序密码或 SSH 私钥；避免将凭据写入命令历史。
