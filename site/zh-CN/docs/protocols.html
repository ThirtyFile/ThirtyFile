SFTP、S3 和 FTP

程序可通过标准协议操作 ThirtyFile 文件。管理员启用后即可使用 SFTP。S3 存储桶和 FTP 接收文件夹是独立功能，提供状态如下说明。

如何选择

使用 WebDAV 将空间挂载为磁盘；使用 SFTP 通过 WinSCP、FileZilla、Cyberduck、OpenSSH 或 rclone 进行加密传输。SFTP 显示与 WebDAV 相同的目录树，遵循相同权限。

SFTP

在控制台 › 常规 › 应用程序与协议开启允许 SFTP 访问，默认关闭。启动时使用 THIRTYFILE_SFTP_ADDR 设置端口（默认 0.0.0.0:2022）。在 Docker Compose 单独发布端口，SFTP 不经过 HTTP 反向代理。

services:
  thirtyfile:
    environment:
      THIRTYFILE_SFTP_ADDR: 0.0.0.0:2022
    ports:
      - "8080:8080"
      - "2022:2022"

将这些项目加入现有 Compose 服务，保留镜像和卷。使用 docker compose up -d 重新启动，仅在必要的网络范围开放所选 TCP 端口。

连接

在客户端选择 SFTP，输入服务器主机名、端口 2022、ThirtyFile 用户名和应用程序密码。此处不接受账号密码。只读应用程序密码无法修改文件，管理员也一样。第一次信任连接前，请核对控制台显示的主机密钥指纹。

sftp -P 2022 amy@files.example.com
# After connecting:
ls
cd "My files"
put report.csv
get report.csv

SSH 公钥

管理员也须开启允许 SSH 密钥。在账号菜单 › SFTP 密钥添加名称和 SSH 公钥，按要求确认当前密码和双因素验证码。私钥请保留在自己的设备。对话框显示指纹和上次使用时间，移除密钥后会停止访问，包括现有连接。

sftp -i ~/.ssh/id_ed25519 -P 2022 amy@files.example.com

SFTP 支持范围

可列出和下载文件、上传、从指定位置续传、创建文件夹、重命名、移动及移除项目（送到回收站）。写入先暂存，关闭文件时才提交，并应用配额、上传限制、版本及活动记录。断线时丢弃未完成写入。接受客户端时间设置但不保存。不提供 Shell、命令执行、SSH rsync、转发或符号链接。每个账号最多五个连接，每个连接最多 32 个打开项目，闲置五分钟后超时。

首次启动时，服务器在数据目录生成 ed25519 主机密钥，请一起备份。更换密钥会改变指纹，客户端应要求你重新确认。

S3 存储桶

将文件夹发布为使用独立 Access Key 的存储桶是另一项开发中的功能，不使用 SFTP 应用程序密码。将 ThirtyFile 连接至现有 S3 存储位置，请参阅存储位置。

FTP 接收文件夹

目前不提供 FTP 接收服务器，仅在无法使用 SFTP 的扫描仪或摄像机有具体需求时规划。将现有 FTP 服务器添加为存储位置是不同功能。

使用案例

服务器可使用 SSH 密钥和 SFTP 脚本上传每晚报表；设计师可使用 Cyberduck 传输大型项目。使用 rclone 时执行 rclone config，选择 SFTP 并设置主机名和端口，核对主机密钥，使用应用程序密码或 SSH 私钥；避免将凭据写入命令历史。
