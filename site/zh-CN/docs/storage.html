文件存放在哪里

在存储文件夹与每个本地文件夹位置中，每个空间都是普通文件夹，里面的文件也都是保留原本名称的普通文件。打开 /storage（compose.yaml 旁的 storage 文件夹），就能找到所有内容：

/storage/company/…              the company space "All files"
/storage/teams/<space name>/…   team spaces
/storage/users/<user name>/…    each user's "My files"

创建空间时，系统会在所选存储位置的文件夹内创建它的文件夹，通常是默认位置（若选择已添加为本地文件夹位置的 NAS，则可能是 /nas/teams/…）。这些是文件夹空间：其他程序、SMB 或扫描器复制进去的文件会出现在 ThirtyFile，网页上的变更也会直接应用到文件夹。

  • 名称。文件夹以空间或用户命名。文件名称不允许的字符会改成 _；ThirtyFile 会隐藏的名称（例如 desktop.ini）前面会加上 _。若同名空间、手动创建的文件夹或已删除空间留下的文件夹已占用该名称，新文件夹会加上编号，例如 teams/Sales (2)。
  • 重命名。重命名空间不会改变文件夹名称，因此依赖其路径的程序、SMB 共享与备份仍可使用。控制面板 › 空间会显示每个空间的文件夹。
  • 删除。删除空间，或删除用户及其文件，只会从 ThirtyFile 移除它们：文件夹与文件仍留在磁盘上，由你决定保留或删除。同名的新空间或用户会取得新的文件夹，不会取得旧文件。将已删除用户的文件移到另一个空间时，磁盘上的文件也会移动。
  • S3、SFTP 与 FTP则使用内容存储区：以文件内容产生名称（ab/cd/…），原本的名称与文件夹结构只保存在 ThirtyFile 的数据库。若以原本的文件夹结构保存，在那里重命名文件夹就必须复制里面的每个文件。当这类位置是默认位置时，新空间会使用内容存储区，之后仍可移到其他位置。

添加位置

  1. 打开控制面板 › 存储位置，点击添加存储位置。
  2. 选择类型，填入地址与登录信息。
  3. 点击测试连接。系统会写入、读回并删除一个小文件；测试成功后才能存储位置。只能写入但无法删除文件的密钥或账号不会通过测试，因为 ThirtyFile 将无法清除已删除的文件。本地文件夹若尚不存在，保存时会创建它（参阅未挂载的磁盘与分享）。S3、SFTP 与 FTP 在保存时会放入一个小型 .thirtyfile-location 文件（参阅一个地方只能有一个位置）。
  4. 若新空间应创建在这里，将它设为默认。

之后编辑位置时，只要服务器、账号、存储桶、SFTP 主机密钥与证书检查设置都未变，已保存的密码或密钥就会保留。变更其中任何一项或重设主机密钥后，必须重新输入密码或密钥。

默认位置只决定新空间创建在哪里：用户的“我的文件”、团队空间，以及新服务器上的“全部文件”。创建团队空间时可以选择其他位置，新用户的“我的文件”也可以有个别位置（参阅个人空间）。每个空间会留在创建时的位置，因此变更默认位置不会迁移现有空间，新文件也会继续存到旧文件所在的位置。只有迁移空间才会改变位置。

列表显示的信息

  • 已用空间：该位置上各空间的文件。文件夹空间使用最近一次检查时的文件夹文件大小；内容存储区则计算所存内容。多个文件内容相同时只计算一次。存储用量提供历史记录。
  • 可用空间：存储文件夹与本地文件夹位置会显示所在磁盘的剩余空间与容量。
  • 文件与空间：该位置的文件夹空间在最近一次检查时的文件数量，加上内容存储区中的内容数量（将光标移到数字上可分别查看），以及该位置上的空间数量。点击空间数量可列出空间的类型、所有者与大小，不会显示里面的内容。

当位置上还有空间、空间正在移入或移出，或内容存储区仍有文件时，不能删除该位置。管理员从自选文件夹创建的文件夹空间（见下方）不属于任何存储位置。

供应商注意事项

  • AWS S3：端点留空。
  • Cloudflare R2：端点为 https://<account ID>.r2.cloudflarestorage.com，区域为 auto。
  • 自托管：RustFS 可使用。选择“自托管”，并勾选“路径式 URL”。
未加密的连接（普通 FTP，或通过 http 的 S3）只接受你自己网络内的地址。

将空间迁移到其他位置

在控制面板 › 空间选择空间，选择迁移到其他位置…。任何空间都能搬到任何其他位置：内容存储区之间、文件夹到内容存储区，或搬到文件夹。对话框显示当前位置与大小，并列出其他位置；位于这台服务器磁盘上的位置也会显示可用空间。目标位置空间不足时，对话框会提示，且无法开始迁移。继续迁移只需容纳尚未复制的部分；同一磁盘内直接迁移文件夹则不需额外空间。

迁移会在后台分三步执行（此处以内容存储区中的空间为例；文件夹空间与迁移到文件夹的流程相似，差异见下方）：

  1. 复制。空间的每个文件、历史版本与回收站中的项目都会复制到新位置，并以文件的 SHA-256 指纹验证每份副本。期间空间仍可使用；迁移期间上传或修改的文件也会复制。
  2. 切换。全部内容就绪后，空间会一次切换到新位置，之后的新文件都会存到那里。
  3. 清理。旧副本会在一分钟后删除，让仍在读取旧副本的下载有时间完成。

切换之前，空间仍在原本位置：停止或取消迁移不会改变用户看到的内容。内容相同的文件在整个系统只保存一次，因此空间与其他位置的空间共享的内容也会一起迁移，那些空间之后也从新位置读取该内容。

将文件夹空间迁移到 S3、SFTP 或 FTP

文件夹空间（位于存储文件夹、本地文件夹位置或自选文件夹的空间）可搬到 S3、SFTP 或 FTP 位置的内容存储区。文件会改以内容存储区形式保存，名称、文件夹、分享链接、权限、回收站与历史版本都保留。

  • 期间只读。从开始迁移到完成或取消，用户可以打开、下载与分享文件，但不能修改；空间会显示提示。暂停或停止的迁移仍保持只读，因为已复制的内容必须维持一致：请继续迁移，或取消以恢复写入。尚在等待第一次执行的迁移不会立刻让空间只读。
  • 文件夹的外部变更。迁移期间，ThirtyFile 以外的程序（例如 SMB 或扫描器）修改、添加或删除的文件，会在切换前检查文件夹时找到并一并复制。更好的做法是让其他程序在迁移完成前停止写入。
  • 名称。内容存储区不区分只有大小写不同的名称，而文件夹可能同时容纳“Report.docx”与“report.docx”。其中一个会加上编号，例如“report (1).docx”；迁移详细信息会显示重命名的数量。
  • 旧文件夹。空间切换到新位置后，系统会移除旧文件夹：只有与已复制内容完全一致的文件才会删除，接着移除清空的文件夹。最后一刻被修改的文件，以及 ThirtyFile 不显示的文件（例如 Thumbs.db）会留下，并列在迁移详细信息中（个人空间只显示数量，保护文件名称隐私）。
  • 空间。每个文件都会经过 ThirtyFile 数据目录中的临时文件，因此该目录必须有足以容纳空间内最大文件的余裕。开始前会检查容量与文件夹是否存在；未挂载的磁盘不会被当成空的空间。

将空间迁移到文件夹

搬到存储文件夹或本地文件夹位置（例如 NAS）的空间，会成为文件夹空间，取得独立文件夹，命名方式与新空间相同（company、teams/<name> 或 users/<user name>，名称已占用时加编号），且复制期间保持只读。

  • 从 S3、SFTP 或 FTP 搬入。每个文件会连同日期写入新文件夹，检查 SHA-256 后重命名到正式位置；回收站存到 .thirtyfile-trash，历史版本存到 .thirtyfile-versions，与其他文件夹空间相同。文件夹无法原样容纳的名称（含不允许的字符、扫描略过的名称如 Thumbs.db，或超过磁盘限制的长度）会改名，详细信息会显示数量。空间切换后，内容存储区会释放文件；若其他空间未使用相同内容，一分钟后便会删除。
  • 从其他文件夹搬入。在同一磁盘上，文件夹会立即直接搬到新位置。在不同磁盘上，会复制文件夹中的全部内容，包括回收站、版本与 ThirtyFile 不显示的文件，每个文件都保留日期并检查大小。期间从外部修改的文件会在切换前检查时找到并复制，之后按上述方式移除旧文件夹。若目标磁盘不区分大小写（例如 CIFS 共享或 exFAT 磁盘），而空间含有只有大小写不同的名称（“Report.docx”与“report.docx”），这些项目不会复制，迁移会停止并列出冲突。请先将每组中的其中一个重命名，再继续迁移。
  • 自选文件夹。显示自选文件夹且不属于任何位置的文件夹空间，也可用同样方式搬到任何存储位置。之后原本的文件夹会移除。

取消迁移到文件夹时，会移除这次创建的文件夹及已复制的内容。

多个空间，或位置上的所有内容

  • 多个空间。在控制面板 › 空间勾选空间（使用各列前的复选框，或表头的全选），选择将 … 个空间迁移到其他位置…。每个空间都有自己的迁移工作，依序执行。已位于目标位置或正在迁移的空间会略过，对话框会显示数量。
  • 位置上的所有内容。在控制面板 › 存储位置对位置选择全部迁移到…，将全部空间（包含个人空间）移到另一个位置。位置会显示进度。全部移走后，若原本是默认位置，系统会提供将目标位置设为默认的选项，并提供删除旧位置的选项。

若目标位于这台服务器的磁盘上，会一次检查所有选择空间合计需要的可用空间。

追踪迁移进度

控制面板 › 迁移先列出未完成的迁移，再列出历史记录。每笔包含空间（用户的“我的文件”以用户命名）、来源与目标位置、已复制文件与字节数、速度、剩余时间与状态。工作执行时页面会自动更新。

  • 一次一个。迁移依启动顺序逐一执行，其余等待。处理器较多且网络快速的服务器可使用同时执行，最多八个迁移一起执行。
  • 暂停与继续。暂停会在当前文件复制完后停止，并保留已复制内容。继续时先进入队列等待，轮到后从停止处接续。ThirtyFile 在迁移期间停止或重启，之后也以相同方式接续。
  • 取消。空间留在原位置，已复制到新位置的内容会移除。
  • 错误。无法复制的文件会尝试三次。若仍有失败，其他文件仍会复制，但迁移会以因错误停止结束，且不切换位置。详细信息列出失败文件与原因（用户的“我的文件”不显示文件名称，因管理员无权查看）。修正原因后继续迁移以重试，或取消工作。无法连接到新位置也会以相同方式停止。
  • 历史记录。完成与取消的迁移会保留 90 天（每个空间最新 20 笔不受天数限制），包含启动者与时间。活动日志也会记录迁移的开始、完成、失败与取消。

迁移完成或取消前，不能删除该空间，也不能删除以它为“我的文件”的用户。

将全部内容复制到其他位置

在控制面板 › 存储位置的位置 … 菜单中选择全部复制到…，会把该位置的全部空间复制到另一个位置，来源保持不变：不会移除文件，空间仍在原处，默认位置也不变。可用于在 NAS、异地存储桶或便携磁盘保存额外副本。若需要反复创建并保留一段时间的快照，请参阅将文件备份到其他位置；保存与还原方式相同。

复制哪些内容

  • 位置上的每个空间，包含个人空间：文件夹（含空文件夹）、文件、回收站与历史版本。对话框会列出空间，显示文件数量、回收站占用量，以及将写入目标位置的大小。
  • 每份内容只存一次。相同内容的文件只保存一次，跨空间也一样。空间的内容无论当前存放在哪里都会复制（整个系统只保存一份相同内容，因此空间的文件内容可能存放在其他位置）。
  • 副本会记录每个文件夹的访问权限供参考。分享链接、收藏与进行中的上传不会复制。
  • 该位置上仅供其他位置空间使用的内容不会包含在内，因为它属于那些空间。

副本存放在哪里

每次复制会在目标位置取得独立文件夹 .thirtyfile-backups/<id>，ThirtyFile 的其他功能不会写入其中。既有内容不会被替换，副本彼此不混合。里面包含：

  • objects/ab/cd/<sha256>：每份内容，以 SHA-256 命名；
  • snapshots/<id>/manifest.jsonl：每个空间、文件夹、文件与历史版本各占一行，包含路径与内容的 SHA-256；
  • snapshots/<id>/complete.json：最后写入，包含列表的 SHA-256。没有此文件的副本不算完整，也不会提供还原；
  • set.json：副本名称、来源位置，以及创建它的 ThirtyFile 信息。

因此即使没有 ThirtyFile，也能找到文件：列表每一行都记录文件路径与存放内容的对象。

目标可能与来源在同一磁盘或存储服务；对话框会提示这样的副本无法承受该磁盘或服务故障。相同路径或互相包含的位置会被拒绝。未加密 FTP 会提示文件以未加密方式传输。若目标位于本服务器磁盘且可用空间不足，会拒绝复制；S3、SFTP 与 FTP 则无法得知剩余容量。

复制期间变更的文件

复制期间空间仍可使用。副本反映创建文件列表时的状态（截至）：之后修改或删除的文件会以当时版本复制，因为内容在复制完成前不会删除。文件夹空间的文件会逐一读取，并检查读取期间是否变更；变更过的会重读。开始前会先检查其他程序造成的文件夹变更。每个文件夹空间文件都完整且符合索引记录，但其他程序在不同时间修改的全部文件不代表同一瞬间的整体状态。

追踪、暂停与错误

控制面板 › 备份列出副本、当前工作与进度。复制在后台执行，一次一项工作；关闭页面后仍会继续。

  • 暂停与继续。暂停会在当前项目完成后停止并保留已复制内容；继续或 ThirtyFile 重启后，从停止处接续。
  • 错误。无法读取的文件会尝试三次。若仍无法复制，工作会以因错误停止结束，且副本不完整。详细信息列出项目与原因（个人空间不显示文件名称）。修正原因后按继续重试。无法连接到位置也会以相同方式停止。
  • 取消。从未完成的副本会从目标位置移除，来源不受影响。
  • 检查备份会从目标位置读回全部内容，检查每份内容的 SHA-256，以及每份列表与其 complete.json 是否一致，并列出丢失或损坏的项目。
  • 删除备份会在确认后从目标位置移除文件夹。可以暂停，但不能取消：删除到一半的副本无法还原。

副本删除前，不能删除持有它的位置或变更该位置的文件夹。移除未使用内容与永久删除文件都不会查看 .thirtyfile-backups，因此不会移除副本；浏览次数也不会打开它（其中列表包含个人空间的文件名称）。活动日志会记录副本的创建、还原、检查与删除。

从副本还原

选择副本并选择还原…，再选择要还原的空间。内容会放入空间本身或你选择的其他公司／团队空间顶层的新文件夹，名称为已还原 <空间> <日期>；不会替换任何既有内容。该空间位置仍保有的内容不会重复复制。

  • 个人空间只能完整还原到其所有者的个人空间，管理员始终看不到里面的文件。
  • 回收站内容默认略过，除非勾选也还原回收站中的项目。
  • 新文件夹继承目标空间的权限。历史版本与副本中记录的访问权限仍留在副本；还原不会给任何人超过目标空间允许的权限。
  • 文件夹无法容纳的名称会拒绝并列出；同一文件夹的名称冲突（例如从文件夹空间的 A.txt 与 a.txt 还原到内容存储区）会加上编号，工作会显示提示。
  • 停止的还原会从停止处接续，不会重复创建项目。

镜像：在多个位置保有相同文件

镜像策略会把某位置上各空间的文件保存到其他位置，检查副本，并在原位置故障时从副本读取。原位置永久丢失时，可将其他位置之一提升为主要位置，空间之后就在那里读写。只有管理员能在控制面板 › 镜像查看与管理镜像。

镜像不是备份。镜像保存当前的文件状态：删除或覆写文件后，镜像也会稍后删除或覆写。若要救回误删或误改的内容，仍需保留备份。镜像让磁盘、NAS 或存储桶故障时文件仍可读取；备份则保留历史状态。

创建镜像

选择新建镜像…（或存储位置 … 菜单中的创建镜像…），然后设置：

  • 要镜像的位置：要复制其空间的来源位置，即主要位置。
  • 副本存放位置：依优先顺序排列的一个或多个位置。每个位置可选择变更后尽快同步（汇整数秒内的变更，再于后台复制），或计划同步（每几分钟、每几小时，或在指定时区每日指定时间）。相同路径或互相包含的位置会被拒绝。
  • 副本数：除源文件外保留几份副本，默认 1 份。副本会使用列表中最前面可用的位置，其余作为备用。若位置数少于副本数，策略会提示并标示为需要处理。
  • 空间：位置上的全部空间（含之后添加的），或只选择勾选的空间。
  • 从副本读取、每几天检查一次（默认 1 天）、变更等待多久后通知管理员（默认 24 小时），以及速度限制。

每份内容在每个位置只复制一次，即使多个文件或空间共享它。文件、历史版本与回收站都会复制。在目标位置，副本存放在内容存储区（ab/cd/<sha256>），无论来源是何种空间。

文件夹空间

文件夹空间（存储文件夹与本地文件夹位置上的全部空间）也能制作镜像。文件从文件夹读取，并在读取期间检查；若有变更就重读。其他程序持续写入的文件（例如记录或信箱）不会让同步整体失败：系统会复制最后一次完整读到的内容，详细信息会标示复制期间有变更（从未完整读到的文件尚无副本，也以相同方式列出；个人空间不显示文件名称）。下次同步会再读取。网页变更会在数秒后复制；其他程序通过 SMB 或扫描器造成的变更，则要等 ThirtyFile 侦测到：服务器本地磁盘约 12 秒，NFS 或 SMB 挂载则在下次定期检查时（默认每 15 分钟，可调整）。每次同步前会先检查文件夹变更。

副本如何维护

  • 写入时检查。每份副本都会先读回并比对 SHA-256，通过后才计入。既有副本若损坏或长度错误，会被替换。
  • 每隔几天会再次检查，也可使用检查副本逐一读回。损坏或丢失的副本会标记，下次同步会从原始内容或其他正常副本补回。
  • 短暂落后。副本在文件变更后稍晚创建，不是同时写入。位置故障前一刻修改的文件可能尚未复制。控制面板 › 镜像显示每个位置是否为最新、变更等待时间，以及最近同步计算时已持有与应持有的内容数量（策略变更后数秒更新）。同步与检查历史保留已完成工作 90 天，每个位置最多最新 1,000 笔，且最新 20 笔不受天数限制。
  • 无法连接的位置会等待，每 5 分钟重试，恢复后补齐。失败的同步会一小时后再试，或按立即同步立刻重试。同步可以暂停、继续与取消；继续时从停止处接续，ThirtyFile 重启后也是如此。
  • 避免误删。清空回收站、永久删除文件、移除未使用内容与待重试的删除都不会删除镜像。只有内容已无人使用，且由创建它的策略执行，才会释放副本。
  • 通知管理员：策略需要处理时（空间原位置或副本位置无法连接、同步失败、副本损坏、位置不足或变更等待超时），会在应用程序与电子邮件以镜像类型通知一次；恢复正常时再通知一次。

主要位置故障时

主要位置无法读取文件内容时（位置离线、内容丢失或文件夹空间的文件夹不存在），若策略允许从副本读取，会改从其他位置上已验证的副本读取。副本是以 SHA-256 命名的相同内容，因此不会比 ThirtyFile 已知的版本更旧。文件夹空间以索引最后记录的文件为准：磁盘故障前数秒由其他程序修改、但 ThirtyFile 尚未侦测到的内容不会出现在副本。每次回退都会记录于服务器记录；活动日志则每个位置最多每 10 分钟记录一次（从镜像读取）。

只有读取会回退。主要位置离线时，上传与空间变更会等待，详见位置离线时；变更绝不会只写入镜像。

提升位置为主要位置

主要位置永久丢失或准备禁用时，选择提升…并指定位置。提升不会自动发生。执行前，对话框会显示两个位置是否可连接、目标落后多少、会转移多少内容与哪些空间，以及缺少多少内容。

  • 已是最新的位置会立即提升。
  • 主要位置仍可连接时，不允许提升落后的位置：请先同步。主要位置无法连接时，可勾选确认“缺少内容的文件在旧主要位置恢复前无法读取”后提升。若检查提升条件期间缺少内容数量改变，系统不会变更任何内容；请重新视图状态后再试。
  • 提升不会改变文件。空间之后在提升的位置读写，它成为主要位置。执行中的同步会停止；当时正在保存到旧主要位置的变更会被拒绝，可以再次尝试。
  • 文件夹空间的全部文件与历史版本若在新主要位置都有已验证副本，就会转成该位置的内容存储区空间，与迁移到 S3、SFTP 或 FTP相同：文件不再位于其他程序可直接修改的文件夹。旧主要位置的文件夹保持原状，不受修改；不再需要后可手动删除。若想恢复文件夹形式，之后可将空间迁移到文件夹。未完整复制到新主要位置的文件夹空间仍留在原处，对话框会列出名称。
  • 旧主要位置保留所有原有内容，之后不再以主要位置身份写入。它成为副本位置，标示旧主要位置，检查中：恢复后会读取并检查副本，替换损坏内容，更新完整后才计为有效副本。内容不会自行搬回。若要恢复原位置，请等它更新完整后再次提升。

提升后请检查策略的位置列表：提升的位置已不在副本列表中；若要保有原本的副本数，请添加其他位置。

移除位置或策略

从列表移除位置、减少副本数或删除策略，都会停止创建新副本，但已创建的副本仍保留且受删除保护。控制面板 › 镜像会显示各位置不再有策略需要的副本数量，并提供移除…。删除前会再次逐一检查：策略仍需要的副本、该位置上的原始内容，以及当前来源位置无法连接的文件夹空间副本都会保留。在此之前，不能删除持有镜像或用作策略来源／目标的位置。

文件夹空间：将服务器文件夹作为空间

存储文件夹或本地文件夹位置上的每个空间都是文件夹空间（参阅文件存放在哪里）。也能把服务器上的现有文件夹（例如 NAS 共享）显示为空间。文件仍以普通文件留在原位置，也可以通过 SMB 或扫描器直接修改。

  1. 将文件夹挂载到容器，例如 -v /srv/shared:/mnt/shared。
  2. 在控制面板 › 空间按新建文件夹空间，输入容器内路径 /mnt/shared。
  3. 像普通团队空间一样添加成员。

用户打开文件夹时，ThirtyFile 会寻找外部变更（数秒内不重复检查；空间正在变更时，例如复制大型文件夹，不检查；被监测的空间也不检查，详见下方。此时列表显示 ThirtyFile 已知的内容）。系统也每 15 分钟检查所有文件夹空间（可在控制面板 › 常规调整），或按检查更改立即执行（大型文件夹会在列表与底部消息显示进度，离开页面仍会继续）。在文件夹内迁移或重命名的文件与文件夹会保留分享链接及权限。检查找到的项目没有上传者（上传者栏与详细信息的创建者显示 —），也不会出现在任何人的最近使用，除非有人打开或编辑它；旧版 ThirtyFile 找到的项目仍保留空间所有者为上传者。系统依磁盘记录的创建时间区分迁移与新项目。若磁盘未记录此信息（部分网络共享），仍可依大小与日期辨识迁移文件，但迁移文件夹会视为删除后重新添加，失去分享链接与权限。

在支持的 Linux 本地文件系统上，变更约 12 秒后会自动出现，因为 ThirtyFile 会监测文件夹。这类空间的定期检查频率降为四分之一（通常的 15 分钟设置下为每小时），补足监测可能漏掉的变更。NFS、SMB、9P 与 FUSE/virtiofs 挂载（含 Docker Desktop 分享的宿主机文件夹）可能不会报告外部变更。无法辨识的文件系统也采用较保守的后备方式：打开文件夹时重新检查（最多每五秒一次），计划检查维持正常间隔。不会写入探测文件来推断宿主机事件是否可用。文件夹很多时可能达到 Linux 监测上限（fs.inotify.max_user_watches，常见为 8,192 或更多）；记录会提示，其余变更通过打开时更新与定期检查发现。在宿主机上使用 sysctl fs.inotify.max_user_watches=524288 提高上限。所有空间的每个文件夹都会计入（每个用户都有自己的空间）。

Windows 与 macOS 的 Docker Desktop。宿主机共享文件夹的变更，会在 ThirtyFile 打开或刷新该文件夹时，以及定期检查时发现，不一定立即出现。仍在写入的文件要等稳定后才显示。重命名或删除可能启动后台检查，以区分移到空间其他位置与真正删除。控制面板 › 空间显示变更是数秒内出现，或于打开时检查，以及实际计划间隔。将间隔设为零会禁用计划，但监测不可用时，打开文件夹仍会检查。随时可使用检查更改做完整检查。

大型文件夹空间检查期间，控制面板 › 空间显示进度；读取文件夹与更新索引耗时超过 10 秒时，记录会分别记下耗时。参考数值：SSD 上首次检查 200,000 个文件，读取约半秒、创建索引约 25 秒；没有更改时重新检查约一至两秒。网络挂载较慢，因为每个文件的大小与日期都需通过网络查询；大型 NFS 或 SMB 文件夹建议保留 15 分钟或更长的定期检查间隔。

网页上的所有操作都会修改文件夹本身：上传、创建文件夹、重命名、迁移、复制、编辑与删除。搬到不同磁盘的空间，或非文件夹空间时，先复制并验证文件，再移除来源；期间在文件夹中被修改的文件会留下，下次检查变更时出现。页面底部消息显示长时间迁移或复制的进度；即使关闭页面，服务器仍会继续。

  • 回收站。删除项目会移到空间文件夹内隐藏的 .thirtyfile-trash，以便还原。清空回收站或从其中删除项目，才会移除文件。
  • 历史版本。在网页保存覆写、上传替换或还原旧版本时，原本的文件会保存在空间文件夹内隐藏的 .thirtyfile-versions（磁盘支持时使用硬链接，否则直接搬入，因此大型文件也能立即保留），ThirtyFile 不会把它们列为普通文件。直接在文件夹内修改（例如通过 SMB）不会保留版本。永久删除文件时也会删除其版本。该文件夹中没有版本参照的文件，存在满一天后会由变更检查移除。
  • 同时编辑。有人在网页编辑期间，文件若在文件夹内被修改，不会覆写外部变更：网页版本会另存为 name (conflict copy)，使用系统默认语言（若跟随浏览器则为英文），与保存者的语言无关。
  • 大小写。在不区分大小写的磁盘（exFAT、NTFS、多数 SMB 共享）上，只有大小写不同的文件夹名称视为既有文件夹。将 Photos 上传到已有 photos 的位置，文件会进入 photos；新建文件夹 Photos 则会提示已存在。
  • 下载。续传会侦测期间已被替换的文件并重新开始。下载期间被替换的文件可能收到混合内容，请重新下载。
  • 只读。创建空间时勾选只读，或之后使用设为只读，只允许浏览、下载与分享。
  • 文件所有者。ThirtyFile 以 THIRTYFILE_RUN_AS 指定的用户写入文件（未设置时为 1000:1000），该用户必须有文件夹写入权限。若其他程序（例如 Samba 分享）以不同用户写入，请让两者加入相同用户组并让文件夹可由用户组写入，或把 THIRTYFILE_RUN_AS 设成其他程序使用的用户。
  • 删除文件夹空间只会从 ThirtyFile 移除空间，文件夹与文件仍留在服务器。
  • 一个文件夹只能属于一个空间或位置：若它包含或位于其他空间文件夹、本地文件夹位置或 ThirtyFile 数据目录内，会被拒绝，避免相同文件重复显示。系统文件夹（如 /etc、/run、/usr 与磁盘根目录）也会拒绝。
  • Office 与系统临时文件（~$…、Thumbs.db、.DS_Store）不会显示；以 .thirtyfile- 开头的 ThirtyFile 内部文件也不会显示。网页与 WebDAV 不允许使用这些名称。解压缩 ZIP 会略过这类项目；从其他空间迁移或复制到文件夹空间时，若来源含有这类名称，会拒绝操作。符号链接、不是有效文本的名称与文件夹内挂载的其他磁盘会略过，检查更改会列出它们（其他人的个人空间只显示数量，不显示空间文件夹）。
  • 仍在复制到文件夹的文件，要等数秒内不再变更后才会出现。
  • 未挂载的磁盘与分享。空间创建时，文件夹内会放入包含空间 ID 的小型隐藏文件 .thirtyfile-space。缺少此文件且突然变空的文件夹，会视为未挂载磁盘或分享：空间保留项目、分享与历史，检查更改会提示。请重新挂载后检查。网页变更只会写入含有该空间标记的文件夹；文件夹丢失或同名路径挂载了不同磁盘时，上传与变更会以文件夹不存在，或这里挂载了不同的磁盘拒绝，且不会重建文件夹。含有其他空间标记的文件夹也不会检查。只有含有该空间标记的文件夹可读取文件。只读空间可能没有标记，因为不一定能写入。标记丢失时，检查更改只会在文件夹仍含有该空间项目时补回，否则只报告文件夹而不变更任何内容。空间内无法读取的子文件夹也以同样方式保留索引项目。若要清空空间，请在 ThirtyFile 删除项目。
  • 同时删除、迁移或还原多个项目遇到错误时，文件夹中已变更的项目会恢复，避免只完成一半。若 ThirtyFile 在同一磁盘迁移项目到空间期间停止，一天后的下次检查会以原名将项目放回原文件夹。若在复制到其他磁盘期间停止，来源仍在原处，未完成副本会在该次检查移除。重命名、移到同一空间其他文件夹、移入或移出回收站，以及保留历史版本时，会先写入隐藏的 .thirtyfile-journal：若执行到一半停止，下次变更检查会把项目放回原处，保留分享、访问权与历史；无法依识别信息区分项目的磁盘（Windows、exFAT）也适用。若原名称期间被其他项目占用，项目会留在迁移后的位置并在那里保留相关信息。若保存已将新内容放入正式位置，新内容会保留，原内容则保存为历史版本。
  • 项目原本所在的文件夹在服务器上被删除或改名时，回收站里的项目仍会保留；还原后会放在空间的最上层文件夹。

检查位置中的内容

控制面板 › 存储位置各位置的 … 菜单还有三个操作，只有管理员可用。

逐步测试

执行文件处理的每个步骤，并列出各步骤耗时：

  1. 连接到位置。
  2. 写入小文件，再读回并比对。
  3. 以普通上传的保存方式上传较大文件（24 MB；S3 使用分段上传），再下载并比对。两者都会显示 MB/s 速度。
  4. 删除测试文件，并确认已移除。

测试文件存入 .thirtyfile-check 文件夹，完成后会删除，步骤失败也一样。测试最多两分钟；连接慢时会略过大文件，而非留下未完成内容。失败步骤会说明原因，例如密钥无法删除文件。

浏览

逐层显示位置中的内容，每页 200 个项目，附大小与日期。此处不能修改内容。可依保存原样下载单一文件，但待删除内容与尚在写入的副本除外。

  • 内容存储区（ab/cd/…，S3、SFTP 与 FTP 位于 blobs 下）：每个项目标示是否有文件、历史版本或回收站项目使用，是否为其他位置内容的镜像、等待删除或完全未使用。有文件使用时会显示空间与文件路径。
  • 存储文件夹与本地文件夹位置上的文件夹空间会标示所属空间。
  • 个人空间保持隐私。其他人的个人空间会显示名称（例如“anna 的个人空间”），但不列出文件、无法在此打开文件夹，也不能下载内容。无论文件夹名称大小写如何（例如 users/anna 写为 USERS/Anna），迁移期间（目标文件夹、已复制内容与清理完之前的旧文件夹），以及其他位置上标示所属空间的镜像，都适用此规则。
  • 符号链接会列出但绝不跟随，SFTP、FTP 与路径中间的链接也一样。
  • 存放副本的 .thirtyfile-backups 不能在此打开，因其中列表含有个人空间的文件名称。副本请在控制面板 › 备份管理。

寻找未使用内容

搜索该位置内容存储区中没有文件、历史版本或回收站项目使用的内容，例如上传途中服务器停止所留下的内容。任务在后台执行，列出结果与总大小。最近 24 小时写入的内容不会处理，因为上传先保存内容再登记；已等待删除的内容也略过。

确认后，移除 N 个项目会只删除列表列出的内容。删除前逐一再次检查；期间又被使用或写入的内容会保留。活动日志会记下移除操作。

在 S3、SFTP 与 FTP，若 .thirtyfile-location 指向其他位置或其他 ThirtyFile 安装，会拒绝搜索与移除：那些内容不是未使用，而是属于它们。

一个地方只能有一个位置

若两个位置指向同一地方，彼此会将对方的文件视为未使用内容。因此不能添加或改为其他位置已使用的地方：同一服务上的相同存储桶与前缀，或同一 SFTP／FTP 服务器上的相同文件夹（相对文件夹依账号分别判定）。

S3、SFTP 与 FTP 的位置也会保存小型 .thirtyfile-location：第一行是位置 ID，第二行是 ThirtyFile 安装 ID，添加位置时写入。早于此功能创建的位置，会在下次连接检查成功时补上。标记指向其他位置或其他 ThirtyFile 安装的地方不能添加，也不会搜索或移除其内容。删除位置时会移除标记。

存储用量与性能

控制面板 › 存储用量显示存储量、时间趋势与保存操作表现，只有管理员可见。顶部依空间类型、回收站与历史版本显示总量，下方每个位置与数据目录各有一张卡片。

操作

位置上的每次读取、写入、删除、列目录与连接检查都会计时并计数，文件夹空间的文件读取与上传也一样。文件夹空间内的重命名、删除与扫描则不测量。计数在内存中进行，每五分钟写入一次，不会拖慢文件操作。服务器停止时最多会丢失五分钟的统计。

  • 任务类型。用户文件操作包含下载、预览、上传与保存。后台任务包含迁移空间、压缩与解压缩、长时间复制与迁移，以及移除未使用内容。检查与测试包含每 20 至 30 秒执行的连接检查与逐步测试。分开统计可避免迁移让上传时间难以判读，也不会把测试视为实际流量。
  • 每次操作时间。以中位数（p50）与第 95 百分位（p95）显示：一半操作比 p50 快，100 次中 95 次比 p95 快。百分位数误差约 10%。读取只计到可开始读取的时间，不含之后传输；写入则计到内容完成保存。同一磁盘可能只需重命名，因此很快。
  • 传输量。每秒读写字节数，取各期间平均。
  • 失败或超时。包含失败、耗时过长或被放弃的操作，例如用户在上传途中离开。中途断线的下载也算失败。用户遇到的错误位于控制面板 › 活动日志的错误标签页，迁移则在控制面板 › 迁移；页面提供这两处的链接。
  • 闲置。没有操作的期间不绘制数据点，图表显示空，不会显示 0 ms。

警示

在警报阈值设置何时提示：磁盘使用率超过指定百分比（默认 90%），或位置最近一小时的操作失败／超时比例超过门槛（默认 5%）。失败警示需要该小时至少 20 次操作。输入 0 可禁用个别门槛。位置离线与测量过期也会警示。警示显示于页面顶部，不会发送电子邮件。

位置离线时

浏览、搜索与整理文件夹仍可使用。打开、下载与上传会暂停，位置恢复后自动继续。有已验证镜像的文件仍可打开与下载，期间空间会标示离线。文件夹空间的文件夹在磁盘上，因此整理文件夹也会暂停。

未挂载的磁盘与分享

本地文件夹位置常是挂载于服务器的磁盘或网络共享，例如 /mnt/nas/thirtyfile。未挂载时，文件夹可能丢失，或只是服务器自身磁盘上的空文件夹。ThirtyFile 不会写入那里，否则文件会落在错误磁盘上，重新挂载分享后反而被隐藏。

  • 标记文件。添加本地文件夹位置或变更文件夹时，若文件夹不存在会创建，并放入记录位置 ID 的 .thirtyfile-location。保存前的测试连接不会创建任何内容，其他流程也不会创建文件夹。
  • 无法使用。之后只有文件夹持有该标记时才会使用位置，否则列表标示离线并显示文件夹不存在，或这里挂载了不同的磁盘，空间的上传与变更也以相同消息拒绝。不会创建或写入任何内容，包括空间文件夹。
  • 恢复。重新挂载磁盘或分享：离线位置每 20 秒检查一次，标记恢复后立即重新使用，不需重启。
  • 磁盘停止响应。网络共享的服务器消失时，可能仍保持挂载却不响应。ThirtyFile 最多等待一分钟（让磁盘有时间启动）；变更开始后则最多等待 20 秒，之后以服务器上文件夹的磁盘没有响应拒绝操作。在磁盘恢复响应前，该空间的变更会立即拒绝，其他功能仍正常。位置检查与健康检查也不会等待它。本地文件夹的内容存储区也同样处理：磁盘步骤超过一分钟会以存储服务暂时无法使用放弃，磁盘恢复前立即拒绝其文件操作，其余 ThirtyFile 功能照常。
  • 标记丢失。文件夹有内容却没有 .thirtyfile-location（例如复制时略过隐藏文件），位置会离线，消息会指出文件应包含的那一行：位置 ID。确认是正确文件夹后，创建只含该行的标记；下次检查就会恢复使用。
  • 其他位置的文件夹。.thirtyfile-location 指向其他位置时会拒绝使用。删除位置会移除标记，让文件夹能再次使用。变更回原文件夹时，若仍有该位置自己的标记，会直接接受。
  • 变更文件夹。位置上还有空间或文件时，只能改到它的完整副本：先复制旧文件夹所有内容（含 .thirtyfile-location）到新文件夹，再变更路径，空间的文件夹会跟著更新。新的空文件夹会拒绝，因为空间文件仍留在旧处。空位置可改成任意文件夹。

新服务器首次启动且存储文件夹为新建或空时，存储文件夹（Docker 内的 /storage，由 THIRTYFILE_STORAGE 设置）也会取得相同标记，内容为 local。磁盘或 NAS 自行创建的项目（lost+found、#recycle、@eaDir、.DS_Store、System Volume Information、$RECYCLE.BIN）不计入非空判定。一旦位置上有文件或空间，就不再接受丢失或空的存储文件夹：ThirtyFile 不会启动，并提示卷可能未挂载。文件夹有文件却缺少 .thirtyfile-location，或标记属于其他位置时也不会启动，因为可能与先前使用的磁盘不同。请检查卷与挂载；确定是正确文件夹后，创建内容为 local 的标记。
