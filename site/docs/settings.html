Settings

Most settings are in the Control panel. A few are given when the container starts.

The settings

SettingDefaultDescription
THIRTYFILE_ADMIN_PASSWORDrandomPassword of the admin account. Used on the first start only
THIRTYFILE_ADMIN_PASSWORD_FILEA file holding that password instead, for example a Docker secret
THIRTYFILE_SECURE_COOKIEfalseSet to true when the site uses HTTPS
THIRTYFILE_TRUST_PROXYfalseSet to true when the site is behind a reverse proxy on the same computer or Docker network. For a proxy on another computer, list its addresses instead, for example 203.0.113.7, 10.1.0.0/16
THIRTYFILE_TRASH_DAYS30Days items stay in the trash. 0 keeps them forever
THIRTYFILE_MAX_UPLOAD_MB0Largest file that can be uploaded. 0 means no limit
THIRTYFILE_DB_CACHE_MB16Database cache per connection, in MB (up to 8 connections). Raise it on a large server with many users
THIRTYFILE_THUMBNAIL_JOBS1 or 2Thumbnails made at the same time: 1 when the server or container has less than 2 GB of memory, else 2
THIRTYFILE_RUN_AS1000:1000User and group the server runs as. The data and storage folders are given to them on start
THIRTYFILE_LOG_FORMATtextjson writes one JSON object per log line, for log collectors
RUST_LOGthirtyfile=infoHow much is logged, for example thirtyfile=debug while looking into a problem
TZUTCTime zone, for example Asia/Taipei

On and off settings accept true/false, 1/0, yes/no and on/off.

With docker run

Add one -e for each setting:

docker run -d --name thirtyfile --restart unless-stopped -p 8080:8080 \
  -v /srv/thirtyfile/data:/data -v /srv/thirtyfile/storage:/storage \
  -e THIRTYFILE_ADMIN_PASSWORD='choose-a-password' \
  -e TZ=Asia/Taipei \
  -e THIRTYFILE_TRASH_DAYS=60 \
  ghcr.io/thirtyfile/thirtyfile:latest

To change a setting later, stop and remove the container, then run the command again with the new value. Your files are kept.

docker stop thirtyfile && docker rm thirtyfile

With Docker Compose

Add them under environment: in compose.yaml, then run docker compose up -d again:

    environment:
      TZ: Asia/Taipei
      THIRTYFILE_TRASH_DAYS: "60"

Memory

ThirtyFile needs about 100 MB of memory while idle and usually stays below 300 MB. Making thumbnails of large pictures takes the most: up to about 280 MB for each thumbnail made at the same time. It runs on a NAS or Raspberry Pi with 1 GB of memory: with less than 2 GB, it makes one thumbnail at a time and lowers the memory a picture may take to decode (pictures above the limit get no thumbnail).

To keep ThirtyFile from using more than a set amount, give the container a memory limit, for example --memory 512m with docker run, or mem_limit: 512m in compose.yaml. ThirtyFile reads the limit on start and adjusts to it.

Where the data is kept

The container uses two folders. Mount a folder of your computer on each:

In the containerContents
/dataAccounts, settings, logs, thumbnails and uploads in progress. Stays small
/storageYour files, in the built-in storage location. Grows with your files

They don't have to be on the same disk: /storage can be a large disk or a NAS mount. Missing folders are created, and on start both are given to user 1000 (see THIRTYFILE_RUN_AS), so there is no need to change their owner yourself.

Other disks can be added as more storage locations: mount them into the container, for example -v /mnt/nas:/nas, then add /nas under Control panel › Storage locations. See Storage locations.
