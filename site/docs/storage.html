Storage locations

Choose where file contents are kept. Different spaces can use different locations.

Where the files are

On the storage folder and on every Local folder location, each space is an ordinary folder, and its files are ordinary files with their own names. You can open /storage (the storage folder next to compose.yaml) and find everything there:

/storage/company/…              the company space "All files"
/storage/teams/<space name>/…   team spaces
/storage/users/<user name>/…    each user's "My files"

A space gets its folder when it is created, in the folder of the storage location it is created on, usually the default one (or /nas/teams/…, say, when it is created on a NAS added as a Local folder location). These are folder spaces: files copied into them by other programs, over SMB or by a scanner, show up in ThirtyFile, and changes made on the web are made in the folder.

  • Names. A folder is named after the space or the user. Characters a file name can't have become _, and names ThirtyFile would hide (desktop.ini, say) get an _ in front. When the folder is already there, because another space has the same name, a folder with that name was made by hand, or a deleted space left it, the new one gets a number: teams/Sales (2).
  • Renaming. Renaming a space doesn't rename its folder, so programs, SMB shares and backups that use the path keep working. Control panel › Spaces shows each space's folder.
  • Deleting. Deleting a space, or a user with their files, removes them from ThirtyFile only: the folder and the files in it stay on the disk, for you to delete or keep. A new space or user with the same name gets a new folder, never the old files. Moving a deleted user's files to another space moves them on the disk.
  • S3, SFTP and FTP keep files in a content store instead: names made of the file's content (ab/cd/…), with the names and folders only in ThirtyFile's database. Renaming a folder there would copy every file in it. Spaces created while one of these is the default location use the content store, and can be moved to another location later.

Adding a location

  1. Open Control panel › Storage locations and click Add storage location.
  2. Choose the type and fill in the address and the login details.
  3. Click Test connection. It writes, reads back and deletes a small file. The location can be saved once the test succeeds. Keys or accounts that may write but not delete files fail it: ThirtyFile could never remove deleted files there. For a Local folder, saving creates the folder when it isn't there yet (see Disks and shares that aren't mounted).
  4. Make it the default if new spaces should be created on it.

The default only decides where new spaces go: users' "My files", team spaces and, on a new server, "All files". When creating a team space you can choose another location, and new users' "My files" can have a location of their own (see Personal spaces). Each space stays on the location it was created on, so changing the default doesn't move any existing space, and their new files keep going where their older ones are. Only moving a space changes its location.

What the list shows

  • Used space: the files of the spaces on the location. For folder spaces, the size of the files in their folders, as of the latest check; for the content store, the contents kept there. Contents that are the same in several files are counted once.
  • Free space: for the storage folder and Local folder locations, how much is free on the disk that holds the folder, and how big it is.
  • Files and spaces: how many contents the content store keeps there, and how many spaces are on the location. Click the number of spaces to list them, with their kind, owner and size. What is in them isn't shown.

A location can't be deleted while a space is on it, while a space is being moved to or from it, or while its content store still keeps files. A folder space an administrator made from a folder of their choice (below) isn't on any location.

Provider notes

  • AWS S3: leave the endpoint empty.
  • Cloudflare R2: endpoint https://<account ID>.r2.cloudflarestorage.com, region auto.
  • Self-hosted: RustFS works well. Choose "Self-hosted" and tick "Path-style URLs".
Connections without encryption (plain FTP, or S3 over http) are only accepted for addresses inside your own network.

Moving a space to another location

Under Control panel › Spaces, select a space in the content store (on S3, SFTP or FTP) and choose Move to another location…. The dialog shows where the space is now and how big it is, and lists the other locations, with the free space of those on this server's disks. A location without enough room for the space can't be chosen.

The move runs in the background, in three steps:

  1. Copy. Every file of the space, its earlier versions and the items in its trash are copied to the new location, and each copy is checked against the file's SHA-256 fingerprint. The space stays in use meanwhile: files uploaded or changed during the move are copied too.
  2. Switch. Once everything is there, the space switches to the new location in one step. Its new files go there from then on.
  3. Clean up. The old copies are deleted a minute later, so downloads that are reading them can finish.

Until the switch, the space is where it was: a move that stops or is cancelled changes nothing for the people using it. A file whose content is the same as another file's is kept only once in the whole system, so content a space shares with spaces elsewhere moves with it, and those spaces read it from the new location too.

Folder spaces can't be moved to another location yet. To put their files elsewhere, move them to another space.

Following moves

Control panel › Moves lists the moves that aren't finished, then the earlier ones. For each: the space (a user's "My files" is named after the user), where it moves from and to, how many files and bytes are copied, the speed and the time left, and its state. The page refreshes by itself while a move runs.

  • One at a time. Moves run one after the other, in the order they were started; the others wait. At the same time lets up to eight run together, on a server with more processors and a fast network.
  • Pause and resume. A paused move stops after the file it is copying and keeps what it copied. Resumed, it waits for its turn, then continues where it stopped. If ThirtyFile stops or restarts during a move, the move continues the same way when it starts again.
  • Cancel. The space stays where it was, and what was copied to the new location is removed.
  • Errors. A file that can't be copied is tried three times. When some still can't be copied, the rest are copied anyway, and the move stops as Stopped by an error without switching. Details lists those files (for a user's "My files", without their names, which administrators don't see) and the reason. Fix the cause, then resume the move to try them again, or cancel it. A new location that can't be reached stops the move the same way.
  • History. Finished and cancelled moves stay on the list, with who started them and when. The activity log also records when each move starts, finishes, fails or is cancelled.

A space being moved can't be deleted, and neither can the user whose "My files" it is, until the move is finished or cancelled.

Folder spaces: a folder on the server as a space

Every space on the storage folder or a Local folder location is a folder space (see Where the files are). You can also show an existing folder on the server, such as a NAS share, as a space. Its files stay where they are, as ordinary files, and can also be changed there, for example over SMB or by a scanner.

  1. Mount the folder into the container, for example -v /srv/shared:/mnt/shared.
  2. Under Control panel › Spaces, click New folder space and enter the path inside the container, /mnt/shared.
  3. Add members as for any team space.

ThirtyFile finds changes made in the folder when someone opens it, and checks every folder space every 15 minutes (change this under Control panel › General), or right away with Check for changes. Files and folders moved or renamed in the folder keep their share links and permissions.

On a disk of the server itself, changes show up by themselves about 12 seconds after they are made: ThirtyFile watches the folders for changes. Those spaces get the regular check only a quarter as often (every hour with the usual 15 minutes), for what watching can miss. That doesn't work for NFS or SMB mounts (the server isn't told about changes other computers make there), so those rely on the regular check. With very many folders, Linux's limit on watched folders (fs.inotify.max_user_watches, often 8,192 or more) can be reached; the log then says so, and the regular check finds the rest. Raise it on the host with sysctl fs.inotify.max_user_watches=524288. Every folder counts, in all spaces together (every user has a space of their own).

While a large folder space is being checked, Control panel › Spaces shows how far it got, and the log says how long reading the folder and updating the index took when it took more than 10 seconds. As a guide, on an SSD the first check of a folder with 200,000 files takes about half a second to read and 25 seconds to index; checking it again when nothing changed takes a second or two. Network mounts are slower to read, since every file's size and date are asked for over the network: keep the regular check at 15 minutes or more for large NFS or SMB folders.

Everything done on the web changes the folder itself: uploading, creating folders, renaming, moving, copying, editing and deleting. Moving to a space on another disk copies the files, checks them, then removes the originals.

  • Trash. Deleted items go to a hidden .thirtyfile-trash folder inside the space's folder, so they can be restored. Emptying the trash, or deleting an item from it, removes the files.
  • Earlier versions. When a file is saved over on the web, replaced by an upload or restored to an earlier version, the file it was is kept in a hidden .thirtyfile-versions folder inside the space's folder (as a hard link where the disk allows one, else as a copy), which ThirtyFile never shows as files. Changes made directly in the folder, over SMB say, don't keep versions. When a file is deleted for good, its versions go at the next check for changes.
  • Editing at the same time. When a file was changed in the folder while someone edited it on the web, it isn't overwritten: the web version is saved next to it as name (conflict copy).
  • Downloads. A download that is resumed notices a file that was replaced in the meantime and starts over. A file replaced while it is being downloaded can arrive mixed; download it again.
  • Read-only. Tick Read-only when creating the space, or use Make read-only on it later, to allow browsing, downloading and sharing only.
  • File owners. ThirtyFile writes files as the user in THIRTYFILE_RUN_AS (1000:1000 unless set). That user needs permission to write in the folder. When other programs (a Samba share, say) write files as another user, give both the same group and make the folder group-writable, or set THIRTYFILE_RUN_AS to the user those programs use.
  • Deleting a folder space removes it from ThirtyFile only; the folder and its files stay on the server.
  • A folder can belong to one space or location only: one that contains, or is inside, another space's folder, a Local folder location's folder or ThirtyFile's data folder is refused, so the same files never show up twice.
  • Temporary files of office programs and systems (~$…, Thumbs.db, .DS_Store) aren't shown. Symbolic links, names that aren't valid text and other disks mounted inside the folder are skipped; Check for changes lists them.
  • A file that is still being copied into the folder appears once it has stopped changing for a few seconds.
  • Disks and shares that aren't mounted. A space's folder holds a small hidden file, .thirtyfile-space, with the space's id, from when the space is created. A folder without it that is suddenly empty is taken to be a disk or share that isn't mounted: the space keeps its items, shares and history, and Check for changes says so. Mount it again and check. Changes made on the web are only made in a folder that holds the space's own file: when the folder is missing, or a different disk with a folder of the same name is mounted there, uploads and changes are refused with The folder isn't there, or a different disk is mounted there, and the folder is never made again. A folder holding another space's file isn't checked either. A folder inside the space that can't be read keeps its items the same way. To empty a space, delete its items in ThirtyFile.
  • When something goes wrong while several items are deleted, moved or restored at once, the ones already changed in the folder are put back, so nothing is half done. If ThirtyFile stops in the middle of moving an item into a space, the item is put back in that folder, under its own name, at the next check a day later.

Checking what a location holds

The … menu of each location under Control panel › Storage locations has three more actions. Only administrators have them.

Test step by step

Runs every step files go through and lists each one with how long it took:

  1. Connect to the location.
  2. Write a small file, then read it back and compare.
  3. Upload a larger file (24 MB) the way uploads are stored, which on S3 is an upload in parts, then download it and compare. Both show their speed in MB/s.
  4. Delete the test files and check that they are gone.

The test files go in a .thirtyfile-check folder and are deleted afterwards, also when a step fails. The test takes at most two minutes: on a slow connection the larger file is skipped rather than left half done. A failed step says why, for example that the keys can't delete files.

Browse

Shows what the location holds, one folder at a time and 200 items per page, with sizes and dates. Nothing can be changed here. Single files can be downloaded as they are stored.

  • Content store (ab/cd/…, under blobs on S3, SFTP and FTP): each item says whether a file uses it, an earlier version, a file in the trash, whether it is waiting to be deleted, or whether nothing uses it. Where a file uses it, the space and the file's path are shown.
  • Folder spaces on the storage folder and Local folder locations are marked with their space.
  • Personal spaces stay private. Other people's personal spaces are named ("Personal space of anna"), but their files aren't listed, their folder can't be opened here, and their content can't be downloaded.
  • Symbolic links are listed but never followed.

Find unused content

Looks through the content store of the location for content that no file, earlier version or item in the trash uses, for example content left behind when a server stopped halfway through an upload. It runs in the background and lists what it found, with the total size. Content written in the last 24 hours is left alone, since uploads store their content before recording it, and so is content already waiting to be deleted.

Remove N items deletes exactly the content on the list, after you confirm. Each item is checked again right before it is deleted: one that was used or written again in the meantime is kept. The removal is recorded in the activity log.

When a location is offline

Browsing, searching and organising folders keep working. Opening, downloading and uploading are paused, and resume by themselves when the location is back. The space is marked as offline in the meantime. In a folder space, whose folders are on the disk, organising folders is paused too.

Disks and shares that aren't mounted

A Local folder location is often a disk or a network share mounted on the server, such as /mnt/nas/thirtyfile. When it isn't mounted, its folder is missing or is an empty folder on the server's own disk. ThirtyFile never writes there: files would land on the wrong disk and be hidden once the share is mounted again.

  • The marker file. Adding a Local folder location, or changing its folder, creates the folder when it isn't there yet and puts a small file in it, .thirtyfile-location, holding the location's id. Test connection before saving creates nothing. Nothing else ever creates the folder.
  • Unavailable. From then on, the location is used only while its folder holds that file. Otherwise the list shows it as offline with The folder isn't there, or a different disk is mounted there, and its spaces refuse uploads and changes with the same message. Nothing is created or written, not even a space's folder.
  • Back again. Mount the disk or share again: the location is checked every 20 seconds while it is offline, and is used again as soon as the file is back, without a restart.
  • Another location's folder. A folder whose .thirtyfile-location names another location is refused. Deleting a location removes its file, so its folder can be used again. A folder that still holds the location's own file, when you change its folder back, is taken as it is.

The storage folder (/storage in Docker, set with THIRTYFILE_STORAGE) gets the same file, holding local, at the first start: when the folder is new or empty. If the storage folder has files in it but no .thirtyfile-location, or one of another location, ThirtyFile doesn't start and says so in the log: it may be a different disk than the one it used. Check the volume or mount. When it really is the right folder, create the file with the word local in it.
