Upgrade and backup

Keep ThirtyFile up to date, and keep a copy of your data somewhere safe.

Upgrading

Back up first. Your files and settings are kept, and the database is updated when the new version starts.

docker run

docker pull ghcr.io/thirtyfile/thirtyfile:latest
docker stop thirtyfile && docker rm thirtyfile
docker run -d --name thirtyfile --restart unless-stopped …   # the same options as when you installed it

Docker Compose

docker compose pull && docker compose up -d

Upgrading from 0.1.0

Version 0.1.0 kept your files in the blobs folder inside /data. They stay there and keep working; the log says so when ThirtyFile starts. To move them to /storage, stop ThirtyFile, move everything inside blobs into the storage folder, and start it again.

Which version you get

TagContents
latestThe newest release. The right choice for most people
1.2, 1.2.3One release line, or one exact release, if you want to decide yourself when to move on

The changes in each release are listed on the releases page.

Backing up

The data and storage folders together contain everything: files, accounts, settings and logs. Stop ThirtyFile while copying them, so that the copy is consistent.

docker run

docker stop thirtyfile
sudo tar czf thirtyfile-backup.tar.gz -C /srv/thirtyfile data storage
docker start thirtyfile

Docker Compose

In the folder of compose.yaml:

docker compose stop
sudo tar czf thirtyfile-backup.tar.gz data storage
docker compose start

This writes thirtyfile-backup.tar.gz into the current folder. Copy it to another computer or disk.

Files on S3, SFTP or FTP are not in the backup. Back up that storage with its own tools. The backup still contains the list of files and who may see them.

Restoring

Unpack the backup where the folders belong, then start the container as usual:

sudo tar xzf thirtyfile-backup.tar.gz -C /srv/thirtyfile

With Docker Compose, unpack it in the folder of compose.yaml instead.

Keep backups safe

A backup contains the keys and passwords of your storage locations and single sign-on, and the logs with visitors' IP addresses. Treat it like a password: store it where only administrators can reach it.
