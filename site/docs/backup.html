Upgrade and backup

Keep ThirtyFile up to date, and keep a copy of your data somewhere safe.

Upgrading

Back up first. Your files and settings are kept, and the database is updated when the new version starts.

docker run

docker pull ghcr.io/thirtyfile/thirtyfile:latest
docker stop thirtyfile && docker rm thirtyfile
docker run -d --name thirtyfile …   # the same options as when you installed it

Docker Compose

docker compose pull && docker compose up -d

Which version you get

TagContents
latestThe newest release. The right choice for most people
1.2, 1.2.3One release line, or one exact release, if you want to decide yourself when to move on
edgeThe newest code, not yet released. For trying out what is coming, not for files you care about

The changes in each release are listed on the releases page.

Backing up

The data volume contains everything: files, accounts, settings and logs.

docker stop thirtyfile
docker run --rm -v thirtyfile-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/thirtyfile-backup.tar.gz -C /data .
docker start thirtyfile

This writes thirtyfile-backup.tar.gz into the current folder. Copy it to another computer or disk.

Files on S3, SFTP or FTP are not in the backup. Back up that storage with its own tools. The backup still contains the list of files and who may see them.

Restoring

Restore into an empty volume, then start the container as usual:

docker run --rm -v thirtyfile-data:/data -v "$PWD":/backup alpine sh -c \
  "tar xzf /backup/thirtyfile-backup.tar.gz -C /data && chown -R 1000:1000 /data"

Keep backups safe

A backup contains the keys and passwords of your storage locations and single sign-on, and the logs with visitors' IP addresses. Treat it like a password: store it where only administrators can reach it.
