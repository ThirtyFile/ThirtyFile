Troubleshooting

Answers to the problems people run into most.

I forgot the administrator password

docker exec -it thirtyfile thirtyfile reset-password admin

Type the new password when asked, so it doesn't stay in your shell history. This also switches the account back on if it was disabled.

docker exec thirtyfile sh doesn't work

The image contains only ThirtyFile itself: no shell and no other programs, which leaves less to keep up to date. Commands of ThirtyFile work as shown in these guides, such as docker exec thirtyfile thirtyfile reset-password …. To look at the files, use the data and storage folders on the host, or docker cp.

An administrator lost their phone and recovery codes

Another administrator can reset it under Control panel › Users. If there is none, turn it off on the server:

docker exec thirtyfile thirtyfile reset-two-factor admin

Share links start with http://127.0.0.1:8080

Set the address people use under Control panel › General › Site URL.

I am signed out right after signing in

THIRTYFILE_SECURE_COOKIE is true, but the site is opened with http://. Open it with https://, or set it to false if you don't use HTTPS.

Everyone gets "too many failed attempts"

Behind a reverse proxy, THIRTYFILE_TRUST_PROXY must be true (or list the proxy's address when it runs on another computer), and the proxy must pass on the visitor's address as in the examples. Otherwise everyone counts as one visitor.

The block lifts by itself after 15 minutes.

After many wrong passwords for one account, from any address, each further attempt for that account has to wait a little longer, up to a minute. The account itself is never locked.

Large uploads fail

Error 413 comes from the reverse proxy. Raise its upload size limit to at least 64 MB, as in the nginx example.

"Permission denied" when starting

On start, the container gives its folders to user 1000. This can't work in two cases:

  • The container is started with --user. Make the folders writable for that user: sudo chown -R 1000:1000 /srv/thirtyfile, with the user's number instead of 1000.
  • A folder is on a network share that doesn't let the owner be changed. The log says Can't give the folder … to user. Set THIRTYFILE_RUN_AS to the user and group that own the files on the share, for example 1026:100.

Looking at the log

docker logs --tail 100 thirtyfile

Checking that it is running

http://your-server:8080/api/health answers with the version and state of the server: "status": "ok", or "degraded" when /data or /storage has less than 1 GB free or a storage location can't be reached. It also lists the free and total space of both folders and whether each storage location is ok or offline, so a monitoring tool (Uptime Kuma, for example) can warn you before the disk is full. The log warns about it too, once an hour. Docker's own health check only fails when the server doesn't answer at all.

How your files are protected

  • Passwords, app passwords, recovery codes and sign-in sessions are stored in a form that cannot be read back.
  • Two-factor sign-in can be required for everyone who signs in with a password.
  • App passwords only reach files, never the account or the Control panel. See Your account.
  • Uploaded files cannot run scripts on the site.
  • A share link stops working when the person who made it loses access to the item.
  • Repeated wrong passwords and app passwords are blocked for 15 minutes.
