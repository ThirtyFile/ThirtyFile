ユーザー

コントロールパネル › ユーザー を開きます。右上の検索欄で、ユーザー名、表示名、メールの一部から探せます。

  • ユーザー名と初期パスワードでアカウントを 作成 します。初回サインインでは、ほかの操作より先に本人がパスワードを選びます。再設定も同じです。再設定は全デバイスからサインアウトし、アプリパスワード、再設定リンク、リンクしたサインイン方法 も削除します。
  • ロール：管理者はコントロールパネルを開けます。標準ユーザーは開けません。
  • 権限：編集（アップロードを含む）、削除、共有。共有は共有リンク、ユーザーと共有…、スペースのメンバー管理を含み、個人用スペースでも必要です。許可がなければ閲覧のみです。一覧の 権限 列も同じ名前を使います。
  • スペースの容量：保存できる量。0 は無制限です。
  • 「マイファイル」を作成：個人用スペース を作るかと、その保存場所。初期値は コントロールパネル › 全般 に従います。
  • ファイルを削除せずサインインを止めるには 無効化 します。アプリパスワード も使えなくなります。
  • 2 段階認証のリセット はスマートフォンと回復コードをなくした人向けです。パスワード再設定と同様に全デバイスからサインアウトし、アプリパスワード を削除します。名前の横の盾は有効になっていることを示します。
  • デバイス はサインイン中のブラウザーを表示します。個別に、または すべてのデバイスからサインアウト で全件を終了できます。アクティビティログと本人のサインイン履歴に記録します。

新しいパスワードの設定、役割の変更、2 段階認証のリセット、管理者の作成は、他の人がアカウントを使えるようにする操作です。コントロールパネル › メールとコントロールパネル › シングルサインオンの設定は、パスワードリセットのメールの送り先と、サインインできる人を決めます。そのため、これらはまずあなた自身のパスワードを求めます。2 段階認証を使っている場合はコードも必要です。シングルサインオンでサインインしている場合は、サインインしてから 10 分以内に行ってください。

使用済み 列はごみ箱を含む個人用スペースの使用量を表示し、なければ 「マイファイル」なし と表示します。

個人用スペース

マイファイル は所有者だけが開けるスペースです。コントロールパネル › 全般 › ユーザー で設定します。

  • 新しいユーザーに個人用スペースを作成 は既定でオンです。オフなら、通常は すべてのファイル など最初に使えるスペースから始まり、「マイファイル」は表示しません。既に持つ人はそのままです。
  • 新しいユーザーの「マイファイル」の場所 は作成先の 保存場所 です。既定の場所 は、各ユーザーを追加する時点の既定の場所に従います。

新規ユーザーのダイアログはこの設定から始まり、シングルサインオンでは メールドメインの規則 で変更できます。後からはユーザーを右クリックするか 編集 を開きます。

  • 「マイファイル」を作成… は、選んだ場所に今すぐ作成します。
  • 「マイファイル」を削除… は、アカウントの削除 と同じく、ファイルを別のスペースへ移すか削除するかを選びます。アカウントとほかのスペースへのアクセスは保持します。

ディスクやネットワーク共有がマウントされていないなど、保存場所のフォルダーが使えなくても、ユーザーの追加と初回シングルサインオンはできます。一覧には マイファイルの作成待ち（保存場所を利用できません） と表示します。次のサインイン時、またはフォルダー復旧後 1 分以内に作成し、待った理由をサーバーログに記録します。

アカウントを削除する

ユーザーを選択して 削除 をクリックします。個人用の マイファイル も削除するため、中のファイルをどうするか選びます。

  • ファイルの移動先 に、他人の個人用スペース、チーム、会社のスペースを選びます。これが既定です。フォルダー構造を保持し、amy のファイル のようなユーザー名に基づく新しいフォルダーに入れます（重複なら番号付き）。ダイアログに名前を表示し、ThirtyFile が作る名前と同じく、操作した人にかかわらずシステムの 既定の言語 を使います（ブラウザーに従う場合は英語）。移動先の容量に数え、足りなければ何も削除せず、別のスペースや容量拡大を求めます。コピーしないため大きくても高速ですが、どちらかが サーバー上のフォルダー なら、アカウント削除前にディスク上で移動します（別ディスクならコピー）。下部のメッセージに進行状況を表示します。ごみ箱は移さず空にします。同僚と共有したフォルダーの共有は維持します。
  • ファイルを完全に削除。元に戻せません。

どちらの場合も、他スペースに追加したファイルと所有するチームスペースは操作した管理者に引き継ぎ、作成した共有リンクは削除します。

ほかを変更せずサインインだけ止めるなら 無効化 してください。ファイルを保持し、共有リンクは再び有効にするまで使えなくなります。

サインインの安全性

コントロールパネル › 全般 › ユーザー で設定します。

  • パスワードのアカウントに 2 段階認証を必須にする：パスワード後に認証アプリのコードを求めます。未設定の人は入る前に設定し、無効にはできません。有効にすると、自分を除くパスワードで入った未設定の人をサインアウトして、次回に設定させます。シングルサインオンはプロバイダーの認証に従い、アプリパスワード はコードなしで引き続き使えます。
  • パスワードの最小文字数：既定は 6、最大 64 です。それ以降に設定、変更するパスワードに適用します。

設定手順は アカウント にあります。

グループ

グループは部署などのメンバー一覧です。個別に追加せず、グループにスペースやフォルダーへのアクセスを与えます。参加、退出にアクセスも従います。グループはコントロールパネル › グループ右上の検索欄で、名前や説明の一部から探せます。

スペース

コントロールパネル › スペース でチームスペースの作成、容量上限、保存先を設定します。別の場所へ移動… は別の 保存場所 へバックグラウンドで移し、コントロールパネル › 移動ジョブ に進行状況を表示します。スペースは右上の検索欄で、名前の一部（個人スペースは所有者名も）から探せます。

  • 新しいチームスペース で 保存場所 も選びます。変更しなければ既定です。新しいフォルダースペース は保存場所に属さない、指定フォルダーを表示します。
  • メンバー ダイアログから追加し、各人に ロール を与えます。同じダイアログで、スペースの共有リンクを作成できるユーザーも選べます。
  • 全員の作成を許可するには コントロールパネル › 全般 で有効にします。作成者と同じ容量上限、既定の保存場所で作り、1 人最大 20 個です。

保持期間とリーガルホールド

組織によっては、一定期間の記録の保存や、案件が続いている間のすべての保存が、誰が何をしても求められます。どちらも、あらゆる削除の方法に対してサーバーが強制します。Web、WebDAV、S3、SFTP、FTP のどれで削除しても項目はごみ箱に移り、保持されているものはそこに残ります。

  • 保持期間。コントロールパネル › 保持期間とリーガルホールド で、スペースに日数を設定します。そのファイルと以前のバージョンは、最後の変更からその日数が過ぎるまで完全に削除できません。削除自体はできます。項目はごみ箱に移り、日付付きで 保持 と表示され、期間が過ぎると自動削除（または 完全に削除）で消えます。期間を設定できるのは管理者だけです。
  • リーガルホールド。管理者は、フォルダーまたはファイル（詳細ペインの 保持）、スペース全体、特定のユーザーが所有するファイル（コントロールパネル › 保持期間とリーガルホールド）に、理由を付けてホールドを設定できます。ホールド中は、対象のものを完全に削除できません。以前のバージョンは、バージョン機能をオフにしていても削除されません（変更で置き換えられる内容が保持されるため）。保持中の項目を含むスペースやアカウントは削除できず、項目をホールド中のフォルダーの外や別のスペースに移動することもできません。フォルダーのホールドは、後から入れた項目にも及びます。ホールドを解除できるのは管理者だけです。設定と解除は、理由とともにアクティビティログに記録されます。

保持されているものは、ごみ箱に 保持 または リーガルホールド中 と表示され、完全に削除、ごみ箱を空にする、自動削除はそれを残したままその旨を知らせます。項目の管理者は、詳細ペインで何が保持しているかを確認できます。コントロールパネルでは、ホールドの一覧（検索と解除）、各ホールドの対象ファイル、CSV ファイルへのエクスポートが使えます。

対象外：フォルダースペース で、ThirtyFile の外、ディスク上で直接削除されたファイル（スペースが再確認され、なしと表示されます）。バックアップやレプリカ内のコピーは、それぞれの削除ルールに従います。

通知メール

共有された、所有・管理するスペースがほぼいっぱい、アクセス期限が近い場合、アプリのベルで全員に知らせます（通知）。メールも送るには コントロールパネル › メール に組織のメールサーバーを入力します。

  • サーバー、ポート、暗号化：STARTTLS（通常 587）、最初から TLS（通常 465）、自分のネットワークのリレーならなし（通常 25）。システムの証明書で確認し、自己署名証明書を許可 は自分のネットワークで確認を省きます。暗号化や証明書確認がない場合はプライベートアドレス（10.x、192.168.x、同じマシンなど）へのみ送り、それ以外はテストで知らせます。
  • 必要なら ユーザー名 と パスワード。暗号化して保存し、再表示しません。空欄なら保持します。サーバー、ポート、暗号化、証明書確認、ユーザー名を変えた場合は再入力してください。保存した値は元のサーバーにのみ送ります。
  • 送信元アドレス：サイト名（ブランド設定）を送信者名として、このアドレスから送ります。サーバー側で送信を許可する必要があります。
  • 通知をメールで送信 をオンにして 保存 します。テストメールを送信 は未保存でもページの設定を使い、問題があれば理由を表示します。

各人の通知設定のアドレスへ送ります。シングルサインオンのアカウントは、設定後の初回サインインで連携先の確認済みアドレスを使います。リンクは コントロールパネル › 全般 の サイトの URL で作り、未設定ならリンクなしです。送信できないメールはサーバーログに記録します。

管理者アラート

小さなチームはダッシュボードをずっと見てはいません。コントロールパネル › 管理者アラートは、管理者の対応が必要なことを、メールアドレスのある管理者全員にメールで送り、希望すれば webhook にも送ります：

  • 使用量のしきい値を超えた、または障害のある保存場所（しきい値はストレージ使用量のものです）と、接続できない保存場所；
  • データフォルダーのディスクの空きが少ない；
  • サインインの失敗：同じアドレスまたは同じアカウントが上限を超えた場合（初期値は 10 分間に 10 回）。名前が出るのは存在するアカウントだけです；
  • 失敗した、または期限を過ぎたバックアップやミラー（アプリ内でも通知されます）；
  • 14 日以内に期限が切れる FTPS 証明書。

それぞれ個別にオフにできます。各問題は開始時と解消時に 1 回ずつ通知され、出たり消えたりする問題はクールダウン（初期値 30 分）が過ぎてから再通知されます。メッセージには保存場所、アドレス、アカウントの名前と数字だけが含まれ、ファイルやフォルダーの名前は含まれません。メールはコントロールパネル › メールのサーバーを使い、各管理者の言語で書かれます。

Webhook には JSON 本文（event、state（firing か resolved）、kind、key、title、params、site、at）が、受信側で確認できる署名付きで届きます。ヘッダー X-ThirtyFile-Timestamp と X-ThirtyFile-Signature: sha256=… で、設定した共有シークレットによるタイムスタンプ・ピリオド・本文の HMAC-SHA256 です。古いタイムスタンプのメッセージは拒否してください。インターネット上の webhook は https が必須で、プライベートネットワークやこのコンピューター上の webhook にはプライベートネットワーク上の webhook を許可が必要です。届かなかったメッセージは 1 分後、5 分後、30 分後、2 時間後、6 時間後に再送し、その後は断念します。結果はページで確認できます。テストを送るで、メールと webhook をすぐに試せます。

管理者が見られるもの

管理者は会社と全チームのスペース、ごみ箱を管理できます。個人用スペースは開けず内容も見られず、容量だけ見られます。ただし アカウントの削除 や 「マイファイル」の削除 では、開けるスペースへ移せます。別の保存場所へ移す こともでき、コピーできないファイルは名前を伏せて表示します。

コントロールパネル › すべての共有リンク で公開リンクを確認し、公開すべきでないものを取り消せます。ほかの人の個人用スペースのリンクは作成者、設定、使用回数のみで、アドレスや対象は見せません。編集はできず削除のみです。アクセスログも同じ情報を省略します。

アクティビティログ は、ほかの人の個人用スペースで誰が何をいつ行ったかを示しますが、対象のファイルやフォルダーは、検索、CSV、アーカイブでも伏せます。フォルダー上の個人用スペースの変更確認は、スキップ件数だけを示し、対象名もフォルダーの場所も示しません。エラー報告はすべての言語で引用された名前を省略します。

パスワードを忘れた場合

メールサーバー と コントロールパネル › 全般 の サイトの URL を設定すると、サインイン画面の パスワードを忘れた場合 が使えます。ユーザー名かメールを入力すると、変更リンクを送ります。リクエストのアドレスではなくサイトの URL で作り、有効期間は 1 時間で 1 回のみ、パスワードとメールのあるアカウントのみ対象です。存在してもしなくても同じ応答を返します。変更すると全デバイスからサインアウトし、アプリパスワードを削除します。どの方法での変更、再設定でも、それ以前の再設定リンクと 2 段階認証待ちのサインインを終了します。

それ以外やメールのないアカウントは、管理者が コントロールパネル › ユーザー で再設定します。管理者自身が忘れた場合は トラブルシューティング を参照してください。

コントロールパネル › S3 バケット には公開したフォルダー、作成者、Access Key、有効期限、最終使用時刻が表示されます。絞り込み、バケットの停止・削除、個別キーの無効化ができます。ファイルはフォルダーに残ります。S3 の設定 を参照してください。

コントロールパネル › FTP 受信フォルダーでは、機器の認証情報、公開フォルダー、一覧／ダウンロード権限、有効期限を管理できます。パスワード更新は既存の接続も終了します。ゲストは公開設定を作成できず、機器の認証情報で Web サイトにはサインインできません。FTP 受信フォルダーを参照してください。

ゲストアカウント

コントロールパネル › ユーザーでアカウントの種類をゲストにすると、外部の協力者に限定したアクセスを提供できます。ゲストが使えるのは、本人または所属グループに明示的に共有されたフォルダーとスペースだけです。全員への権限は適用されません。ゲストにはマイファイルがなく、スペースや共有リンクの作成、他の人への権限付与はできません。管理者、マネージャー、所有者にもなれません。WebDAV と SFTP のアプリパスワードは、同じ共有フォルダーの範囲で使えます。

既存アカウントをゲストに変更するときは、変更内容のプレビューを確認し、自分の本人確認を行います。個人ファイルは保存されますが、そのゲストからはアクセスできなくなります。既存の共有リンクとプロトコル公開も停止します。プレビューには、ロールや終了日を変更する直接の権限が表示されます。チームスペースの所有権は先に移譲してください。グループにマネージャーや所有者の権限、終了日なしの権限、ゲストの上限を超える期限がある場合、変換やゲストの追加の前に修正が必要です。他のグループメンバーの権限は自動では変更されません。通常のアカウントに戻すと保存された個人ファイルを使えますが、直接の権限の変更は元に戻りません。

アクセス権の見直し

コントロールパネル › アクセス権の見直しは、誰が何にアクセスできるかを 1 ページに表示します。定期的な見直し（ISO 27001 のような監査が求めるもの）に使えます：

  • スペースとフォルダー：各チームスペースと会社のスペースのメンバーと役割、その中で個別に共有されたフォルダー、制限付きフォルダーとそこにアクセスできる人。個人スペースは件数だけを表示し、名前は表示しません。
  • 終了日のあるアクセス権（期限の近い順）。
  • 人：各アカウント（またはゲストのみ）について、直接・グループ経由・全員として権限が与えるスペースとフォルダー、役割と終了日、アプリパスワードと SSH キーの最終使用日時。
  • 外部からのアクセス：共有リンク（作成者、期限、パスワードの有無、最終アクセス）、S3 キー、FTP 受信フォルダー。

終了したものは表示されません。管理者自身のアクセス権も表示されません。管理者は権限なしでチームと会社のスペースを管理します。各部分は CSV にエクスポートでき、印刷でページ全体を印刷できます。見直しの依頼で間隔（30・90・180・365 日ごと）を選ぶと、期限に管理者へ通知されます。終わったら見直し済みにするを押してください。アクティビティログに記録され、次の見直しはそこから数えます。
