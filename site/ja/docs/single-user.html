シングルユーザーモード

ThirtyFile を、サンドボックス内で一人が使うファイルマネージャーとして使います。サインインもアカウントもなく、管理するのは 1 つのフォルダーだけです。

何が変わるか

シングルユーザーモードは、自分だけがアクセスできる場所のためのものです。サンドボックス、仮想マシン、自分のコンピューター上のコンテナーなどです。ページを開けば、ファイルがそこにあります。明示的に有効にしない限りオフで、通常のサーバーには影響しません。

  • サインインなし。ページにアクセスした人はみな同じ人として扱われます。アカウント、パスワード、2 段階認証コードはありません。
  • フォルダーは 1 つ。ファイルは、選んだフォルダー（THIRTYFILE_FILES）の中の通常のファイルです（名前を付けた複数のフォルダーも指定できます。下記参照）。閲覧、アップロード、ダウンロード、作成、編集、名前の変更、移動、削除ができ、プレビュー、検索、タグ、ごみ箱、エディターはいつもどおりです。フォルダーの外から行った変更も表示されます。
  • 複数人向けの機能はありません。ユーザーとグループ、権限、共有リンク、ゲスト、コントロールパネル、通知、WebDAV、S3 バケット、FTP 受信フォルダーは、隠されているだけでなく無効です。サーバーは応答しません。SFTP もオフのままです。
  • そのフォルダーだけ。サーバーはそのフォルダーの中だけを読み書きします。外を指すリンクは、すべてのフォルダースペースと同じようにスキップされます。

Docker で動かす

docker run -d --name thirtyfile --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v /srv/thirtyfile/data:/data \
  -v /srv/work:/files \
  -e THIRTYFILE_SINGLE_USER=true \
  -e THIRTYFILE_FILES=/files \
  -e THIRTYFILE_RUN_AS=1000:1000 \
  ghcr.io/thirtyfile/thirtyfile:latest
部分役割
-p 127.0.0.1:8080:8080このコンピューターだけにページを公開します。127.0.0.1: がないと、Docker はファイアウォールを通り越して、コンピューターがつながるすべてのネットワークにポートを開きます
-v /srv/work:/files管理するフォルダー。広い範囲ではなく、サンドボックス内の 1 つのフォルダーをマウントしてください。サーバーが触れられるのはそこだけです
THIRTYFILE_SINGLE_USER=trueこのモードを有効にします
THIRTYFILE_FILES=/filesコンテナーから見たフォルダーのパス。必須です
THIRTYFILE_RUN_AS=1000:1000サーバーを実行するユーザー。/files 内のファイルを変更できる必要があります。そのフォルダーの所有者を指定してください（id -u と id -g）

/data フォルダーには、インデックス、サムネイル、設定が保存されます。ファイルのフォルダーの中に置くことはできず、このモード専用です。シングルユーザーモードで作ったデータフォルダーは通常のサーバーでは起動できず、その逆も同じです。後で別のフォルダーを選ぶと、そのフォルダーが表示されます。以前のフォルダーはそのまま残ります。

複数のフォルダー

同じ画面で複数のフォルダーを扱うには、フォルダーごとに名前を付けます。それぞれがその名前の独立したスペースになり、「すべてのスペース」に並んで、ナビゲーションやファイル操作はいつもどおりに使えます。名前は自由に決められ、ディスク上のフォルダー名と同じである必要はありません。

-e THIRTYFILE_FILES=Workspace=/workspace,Home=/home/sandbox

各フォルダーは、上の /files と同じようにコンテナーにマウントします。項目はカンマで区切り、すべてのフォルダーに名前を付けてください。フォルダーを別のフォルダーの中に置くことはできず、データフォルダーもすべてのフォルダーの外に置きます。後から一覧から外したフォルダーはディスク上にそのまま残り、再び名前を付ければ表示されます。名前なしのパスを 1 つだけ書く場合は従来どおりで、「My files」と表示されます。

読み取り専用のフォルダー

ThirtyFile が新しいファイルを作れないフォルダー（:ro でマウントしたものなど）は、読み取り専用のスペースとして表示されます。ファイルは開いたりダウンロードしたりでき、中身は何も変わらないため、ごみ箱や以前のバージョンはありません。別のディスクやマウントにあるために THIRTYFILE_FOLDER_STATE を使えないフォルダー（保存場所を参照）も同じように表示されます。ThirtyFile は起動時に各フォルダーを調べ、読み取り専用にした理由をログに出力します。権限やマウントを変えた後は再起動してください。

-v /mnt/assets:/assets:ro \
  -e THIRTYFILE_FILES=Workspace=/workspace,Assets=/assets

シンボリックリンクはたどりません。リンク先の内容を開くには、上の Assets のように、そのフォルダーを別のフォルダーとして指定してください。

自分のコンピューターから開く

コンテナー内ではサーバーはすべてのアドレスで待ち受け、Docker は公開したポートだけを通します。-p 127.0.0.1:8080:8080 を使うと、Docker を動かしているコンピューターで http://localhost:8080 を開けます。Docker を使わない場合、サーバーは既定で 127.0.0.1:8080 だけで待ち受けます（THIRTYFILE_ADDR で変更できます）。

サンドボックスが別のマシンや仮想マシンのときは、自分のコンピューターからポートを転送すると、ページは localhost として届きます。

ssh -L 8080:127.0.0.1:8080 user@sandbox

その後、自分のコンピューターで http://localhost:8080 を開きます。多くのサンドボックスや開発用コンテナーには、同じことをするポート転送の設定があります。

サーバーが応答するのは localhost、127.0.0.1、[::1] だけです。別の名前で届いたページには「unknown host name」と表示されます。転送ツールやプロキシがページに独自の名前を付ける場合は、その名前を指定してください。

-e THIRTYFILE_ALLOWED_HOSTS=sandbox.example.com

誰がアクセスできるか

サインインがないため、ポートにアクセスできる人は誰でもフォルダー内のすべてのファイルを扱えます。他の人を締め出すのは、ThirtyFile ではなく、サンドボックスとその周りのネットワークです。ポートはループバックアドレスだけ、または自分で用意した転送の背後に置き、ネットワークやインターネットには公開しないでください。待ち受けるアドレスがループバックアドレスでないとき、ThirtyFile は起動時にログへ警告を書きます。Docker 内では当然そうなるので、重要なのは公開したポートです。

閲覧している Web サイトは localhost にリクエストを送れるため、ThirtyFile は次のことを引き続き行います。

  • 別の Web サイトから来たとブラウザーが伝えるリクエストは拒否されます。Origin がページ自身のものでない変更も同様です。
  • このコンピューターの名前ではない名前でのリクエストは拒否されます。自分の名前をあなたのコンピューターに向けさせる Web サイト（DNS リバインディング）を防ぎます。
  • ファイルには、選んだフォルダーの下からしかアクセスできません。

同じコンピューター上のプログラムは、引き続きそのポートを使えます。信頼できないものがある場合は、サンドボックスのネットワークをそれらから分けてください。

設定

変数既定値役割
THIRTYFILE_SINGLE_USERfalseシングルユーザーモードを有効にします
THIRTYFILE_FILES管理するフォルダーのフルパス。または 名前=/パス,名前=/パス で複数指定（下記参照）。このモードでは必須で、どれもデータフォルダーを含んだり、その中にあったり、互いに含み合ったりしてはいけません
THIRTYFILE_ADDR127.0.0.1:8080サーバーが待ち受ける場所（通常のサーバーは 0.0.0.0:8080。Docker イメージは自分で設定します）
THIRTYFILE_ALLOWED_HOSTSlocalhost のほかに、ページを開ける名前をカンマで区切って指定します

THIRTYFILE_TRASH_DAYS や THIRTYFILE_MAX_UPLOAD_MB などその他の設定は、設定のとおりに動作します。バックアップやストレージの場所などはコントロールパネルの機能で、ここでは使えません。フォルダーをコピーするか、サンドボックス自体のスナップショットを使ってください。

通常のサーバーに戻す

新しいデータフォルダーで通常のサーバーを起動し、そのフォルダーをスペースとして追加します。ファイルはデータフォルダーの中にはなかったので、エクスポートは不要です。
