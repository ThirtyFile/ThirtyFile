オンにする

コントロールパネル › 監視 を開き、トークン を作成します。トークンは一度しか表示されず、サーバーにはそのフィンガープリントだけが残るので、今コピーしてください。そのあと メトリクスのリクエストに応答する をオンにします。数値はサイトの /metrics にあり、Authorization: Bearer <トークン> を送るリクエストだけが受け取れます。オフのときはこのアドレスは存在しません。

リクエストを受け付けるアドレスやネットワーク（203.0.113.7、10.1.0.0/16）を一覧にできます。ほかのアドレスからのリクエストは、トークンを調べる前に拒否されます。一覧がなければ、どのアドレスからでもトークンがあれば受け付けます。新しいトークンは古いものをすぐに置き換えます。間違ったトークンは間違ったパスワードと同じようにそのアドレスの失敗として数えられ、20 回続くとしばらく待たされます。トークンの作成と変更にはパスワードが必要で、アクティビティログにも記録されます。

Prometheus での設定

トークンを認証情報にしたスクレイプジョブを追加します。

scrape_configs:
  - job_name: thirtyfile
    scheme: https
    authorization:
      credentials: tfm_…
    static_configs:
      - targets: ["files.example.com"]

アラートルールの例：

groups:
  - name: thirtyfile
    rules:
      - alert: ThirtyFileDown
        expr: up{job="thirtyfile"} == 0
        for: 5m
      - alert: ThirtyFileLocationDown
        expr: thirtyfile_storage_location_up == 0
        for: 5m
      - alert: ThirtyFileDiskNearlyFull
        expr: thirtyfile_disk_free_bytes / thirtyfile_disk_total_bytes < 0.1
        for: 15m
      - alert: ThirtyFileBackupOverdue
        expr: thirtyfile_backup_last_complete_age_seconds > 2 * 86400
      - alert: ThirtyFileBackgroundLoopStuck
        expr: time() - thirtyfile_background_last_success_timestamp_seconds{job="maintenance"} > 3 * 3600
      - alert: ThirtyFileCertificateEnds
        expr: thirtyfile_ftps_certificate_expiry_seconds < 14 * 86400

どんな数値があるか

名前はすべて thirtyfile_ で始まります。公開された名前は変えません。新しいバージョンで数値が増えることはあります。

名前ラベル内容
thirtyfile_build_infoversionバージョン。値は常に 1
thirtyfile_process_start_time_secondsサーバーが起動した時刻
thirtyfile_process_uptime_seconds起動してからの秒数
thirtyfile_process_resident_memory_bytes使用しているメモリ（Linux）
thirtyfile_process_open_files開いているファイルと接続（Linux）
thirtyfile_process_threadsスレッド数（Linux）
thirtyfile_http_requests_totalmethod, code応答したリクエスト（メソッドとステータスの種類別）
thirtyfile_http_request_duration_secondsリクエストから応答開始までの秒数（ヒストグラム）
thirtyfile_http_requests_in_flight処理中のリクエスト
thirtyfile_sign_in_events_totaleventサインインログと同じ名前のイベント：login、bad_password、locked、2fa_failed など
thirtyfile_sessions終了していないサインインセッション
thirtyfile_accountsstateアカウント。active または disabled
thirtyfile_storage_operations_totallocation, op, outcomeストレージの場所への操作（結果別）：ok、error、timeout
thirtyfile_storage_bytes_totallocation, opストレージの場所から読み書きしたバイト数
thirtyfile_storage_operation_duration_secondslocation, opストレージ操作にかかった時間（ヒストグラム）
thirtyfile_storage_location_uplocation場所が使えれば 1、使えなければ 0
thirtyfile_storage_location_live_bytes, _trash_bytes, _version_byteslocation場所にある各スペースのファイルのバイト数：現在、ごみ箱、以前のバージョン
thirtyfile_storage_location_disk_free_bytes, _disk_total_byteslocation場所があるディスクの空きと全体のバイト数
thirtyfile_disk_free_bytes, thirtyfile_disk_total_bytesvolumeデータフォルダーとストレージフォルダーがあるディスクの空きと全体のバイト数（data、storage）
thirtyfile_database_size_bytes, thirtyfile_database_wal_size_bytesデータベースとその先行書き込みログの大きさ
thirtyfile_tasks_runningkind実行中のタスク（圧縮、展開、コピー、移動など）
thirtyfile_tasks_finished_totalkind, outcome終了したタスク。done または failed
thirtyfile_background_last_success_timestamp_secondsjobバックグラウンドのループが最後に処理を終えた時刻（maintenance、usage_sampler、location_checks、backup_jobs、replica_jobs、space_moves）
thirtyfile_backup_last_complete_age_secondspolicyオンのポリシーが最後に完全なスナップショットを作ってからの秒数。1 つも作っていなければ出力されません
thirtyfile_backup_policiessnapshotオンのポリシー（完全なスナップショットがあるものとないもの）
thirtyfile_replica_sync_age_secondspolicyレプリカポリシーのすべてのターゲットが最新になってからの秒数。一度も同期していないターゲットがあれば出力されません
thirtyfile_content_search_queue, thirtyfile_content_search_failed検索のために読み取り待ちのファイルと、読み取れなかったファイル
thirtyfile_alert_deliveries_pending, thirtyfile_alert_deliveries_failed送信待ちのアラートメッセージ（メール、webhook）と、あきらめたもの
thirtyfile_alerts_firingkind発生中の管理者アラート（種類別）
thirtyfile_ftps_certificate_expiry_secondsFTPS 証明書が切れるまでの秒数（切れたあとは負の数）
thirtyfile_emails_totaloutcome送信したメール。sent または failed
thirtyfile_metrics_requests_totaloutcomeこの数値へのリクエスト：ok、unauthorized、forbidden、too_many

Grafana

thirtyfile-grafana.json をインポートし（Dashboards › New › Import）、使っている Prometheus を選びます。リクエストと応答時間、サインイン、ストレージ操作、ディスク、タスク、バックアップ、発生中のアラートが表示されます。

ダッシュボード

コントロールパネル › ダッシュボード は Prometheus なしで使えます。サーバーが正常かどうか（/api/health と同じ確認で、理由も表示）、発生中の管理者アラート、サインイン中と利用中の人数、タスク、アップロード、ディスクの空き容量、そして直近 24 時間または 7 日間のグラフ（リクエストとサーバーエラー、応答時間、ユーザーと作業、ストレージ操作、サインイン失敗、ディスクの空き容量）を表示します。最近のサーバーエラーとサインイン失敗も一覧にし、アクティビティログ へのリンクがあります。グラフは 5 分ごとに記録して 8 日間保持する数値から作られ、/metrics がオフでも動きます。数値がない区間は、サーバーが動いていなかったことを表します。

含まれないもの

人名、ファイル名、訪問者のアドレス、パスは含まれません。ラベルは決まった言葉（メソッド、タスクの種類、イベントの種類）と、管理者が付けたストレージの場所とバックアップポリシーの名前だけです。名前に引用符や改行が含まれるときは、形式の決まりどおりにエスケープされます。

サーバーを再起動すると、カウンターは 0 から数え直します。Prometheus はそれを前提にしています（rate() と increase() が扱います）。調べないと分からない数値（セッション、アカウント、ディスク、データベース、バックアップ）は、監視がオンの間 15 秒ごとに調べてメモリに保持します。メトリクスの取得はロックも取らず、ディスクも読まないので、頻繁に取得しても負担になりません。メモリ、開いているファイル、スレッドの数は Linux でだけ表示されます。
