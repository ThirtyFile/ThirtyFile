SFTP、S3、FTP

プログラムから標準プロトコルで ThirtyFile のファイルを操作できます。管理者が有効にすると SFTP を利用できます。S3 バケットと FTP 受信フォルダーは別の機能です。提供状況は以下を確認してください。

用途に合わせて選ぶ

空間をドライブとして割り当てるには WebDAV を使用します。WinSCP、FileZilla、Cyberduck、OpenSSH、rclone で暗号化転送するには SFTP を使用します。SFTP のツリーと権限は WebDAV と共通です。

SFTP

コントロールパネル › 一般 › アプリとプロトコルで SFTP アクセスを許可を有効にします。初期状態では無効です。起動時に THIRTYFILE_SFTP_ADDR でポートを指定します（既定値 0.0.0.0:2022）。Docker Compose で専用ポートを公開してください。HTTP リバースプロキシは経由しません。

services:
  thirtyfile:
    environment:
      THIRTYFILE_SFTP_ADDR: 0.0.0.0:2022
    ports:
      - "8080:8080"
      - "2022:2022"

既存の Compose サービスにこれらを追加し、イメージとボリュームを保持してください。docker compose up -d で再起動します。必要なネットワーク範囲だけで選択した TCP ポートを開放してください。

接続

クライアントで SFTP を選び、サーバーのホスト名、ポート 2022、ThirtyFile のユーザー名とアプリパスワードを入力します。アカウントのパスワードは使えません。読み取り専用アプリパスワードでは管理者もファイルを変更できません。初回接続を信頼する前に、コントロールパネルのホストキーのフィンガープリントを確認してください。

sftp -P 2022 amy@files.example.com
# After connecting:
ls
cd "My files"
put report.csv
get report.csv

SSH 公開キー

管理者は SSH キーを許可も有効にします。アカウントメニュー › SFTP キーで名前と SSH 公開キーを追加してください。求められた場合は現在のパスワードと二要素認証コードを確認します。秘密キーは自分の端末に保管してください。ダイアログにはフィンガープリントと最終使用日時が表示され、削除すると既存の接続からのアクセスも停止します。

sftp -i ~/.ssh/id_ed25519 -P 2022 amy@files.example.com

SFTP の対応範囲

アクセス権は ThirtyFile のロールと共有設定で管理します。Unix 所有者や chmod 600 などの権限変更は拒否され、作成時に指定するモードは参考値として扱います。rclone では disable_hashcheck = true を設定してください。リモートチェックサムを計算するシェルコマンドは提供しません。コントロールパネルにアクセスできない場合は、管理者から正しいホストキーのフィンガープリントを取得してください。

一覧表示、ダウンロード、アップロード、指定位置からの再開、フォルダー作成、名前変更、移動、削除（ごみ箱へ）に対応します。書き込みは一時保存され、ファイルを閉じると容量制限、アップロード上限、バージョン、活動ログを適用して確定します。切断時は未確定の書き込みを破棄します。クライアントから送られた時刻設定は受け付けますが保存しません。シェル、コマンド実行、SSH 経由の rsync、転送、シンボリックリンクには対応しません。アカウントごとに接続は五つ、接続ごとに開ける項目は 32 個、無操作タイムアウトは五分です。

初回起動時にデータフォルダーに ed25519 ホストキーを生成します。データのバックアップに含めてください。交換するとフィンガープリントが変わり、クライアントが変更の確認を求めます。

S3 バケット

チームや会社のフォルダーをバケットとして公開します。各 Access Key はそのフォルダーだけにアクセスし、作成者の現在の権限で操作します。既存の S3 サービスをストレージとして追加する機能とは異なります。

エンドポイントの設定

コントロールパネル › 一般 › アプリとプロトコル › S3 で S3 を有効にし、s3.files.example.com などの専用ホスト名とリージョン（既定は us-east-1）を指定します。初期状態では無効です。プロキシはこのホスト名をサイトと同じ HTTP ポートへ転送するため、Docker ポートの追加は不要です。署名に使われる元の Host ヘッダーを保持してください。S3 ホスト名には有効な HTTPS 証明書と DNS レコードが必要です。

既存の証明書設定を持つ S3 ホスト名の HTTPS server ブロックに次の設定を追加します。ディスク容量やスペースのクォータに合ったアップロード制限を設定してください。

location / {
    proxy_pass http://thirtyfile:8080;
    proxy_set_header Host $http_host;
    proxy_request_buffering off;
    proxy_buffering off;
    client_max_body_size 0;
}

公開とキー

フォルダーを右クリックして S3 バケットとして公開… を選ぶか、プロパティ › S3 バケット を開きます。小文字、数字、ハイフンで 3～63 文字の一意な名前を指定します。フォルダーの名前を変更したり移動したりしても、バケット名は変わりません。

管理者はチームまたは会社のフォルダーを公開できます。スペースの管理者には、アカウントの共有権限と スペースの管理者によるバケットの公開を許可 の有効化が必要です。個人スペースと共有リンクの作成者を 誰も許可しない にしたスペースは公開できません。フォルダーがごみ箱にある間、作成者の管理権限がなくなった場合、スペースを無効にした場合はバケットが停止します。権限やフォルダーを復元すると、有効なバケットは再び使えます。

バケットの公開とキーの作成では、現在のパスワードと、2 段階認証を使っている場合はコードを求められます。キーはバケットを公開した人として動作するため、キーの作成や停止したバケット・キーの再開ができるのは、公開した人か管理者だけです。このフォルダーを管理する他の人は、停止や削除ができます。変更はすべてアクティビティログに記録されます。

説明、読み取り専用または読み書きの権限、任意の有効期限を指定してキーを作成します。Secret Key は一度だけ表示されるため、すぐ保存してください。キーはデータフォルダーの secret.key で暗号化されます。バックアップガイド に従ってこのファイルを保管してください。有効なキーの期限が三日以内になると、作成者にアクセス終了の通知が届きます。読み取り専用のスペースには読み取り専用キーだけを作成できます。

キーは個別に停止または削除でき、他のキーには影響しません。コントロールパネル › S3 バケット では全バケット、作成者、キー、最終使用時刻を確認できます。バケットを停止すると全キーのアクセスが止まります。バケットやキーを削除してもファイルは残ります。Access Key はサイト、SFTP、WebDAV へのログインには使えません。操作履歴にはバケットとキーの説明が記録され、認証情報は記録されません。

クライアント

プログラムで S3 互換サービスを選び、エンドポイント https://s3.files.example.com、リージョン us-east-1（または設定したリージョン）、パス形式の URL、バケットのキーを指定します。仮想ホスト形式の URL、ACL、サーバー側暗号化設定は有効にしないでください。

aws cli では名前付きプロファイルを対話形式で設定し、認証情報をコマンド履歴に残さないでください。アドレス形式を path にし、各コマンドでエンドポイントを指定します。

aws configure --profile thirtyfile
aws configure set s3.addressing_style path --profile thirtyfile
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 ls s3://backups/
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 cp report.csv s3://backups/report.csv

rclone では rclone config を実行し、S3、プロバイダー Other を選び、キーを対話形式で入力します。エンドポイントとリージョンを指定し、force_path_style を有効にし、disable_checksum を true にして rclone の独自 MD5 メタデータを無効にします（S3 の Content-MD5 は転送を検証します）。ACL とサーバー側暗号化は未設定にします。rclone copy はファイルを追加しますが、rclone sync は宛先のファイルを削除する場合があります。

ThirtyFile は rclone の x-amz-meta-mtime を現在のコンテンツバージョンに結び付けて保持し、同じキーへのコピーによる時刻の更新もサポートします。他のカスタムメタデータには対応しません。no_system_metadata ではこのタイムスタンプの送信を止められないため、無効のままにしてください。S3 以外のファイルの更新時刻は変わりません。

バックアップとその他の用途

restic を使う場合は Backups フォルダーを backups として公開し、読み書きキーを作成します。AWS_ACCESS_KEY_ID と AWS_SECRET_ACCESS_KEY は保護された認証情報ストアから読み込みます。リポジトリのパスワードは S3 キーとは別です。安全に保管し、専用の空のフォルダーだけを初期化してください。

restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path init
restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path backup ./documents

Duplicati や Synology Hyper Backup では、同じエンドポイント、リージョン、パス形式を使う S3 互換の保存先を設定できます。バックアップリポジトリのファイルをブラウザーで編集しないでください。このエンドポイントは各ツールの保存先であり、ThirtyFile 自体のバックアップやレプリカのポリシーとは別です。

取引先に価格表を読んでもらう場合は Price lists フォルダーを price-lists として公開し、90 日後に期限が切れる読み取り専用キーを作成します。データチームでは rclone や aws cli のジョブごとにキーを作成すると、個別に停止できます。

フォルダーへの対応と制限

a/b/c.txt は入れ子のフォルダーとファイルに対応し、PUT は必要な親フォルダーを作成します。/ で終わる空のオブジェクトはフォルダーです。一覧は UTF-8 のバイト順で、プレフィックス、区切り文字、件数を制限したページに対応します。親への移動、空のパス要素、不正な文字、前後の空白を含む名前は拒否します。大文字と小文字を区別しないスペースでは、大文字と小文字だけが異なる名前の競合を拒否します。

DELETE はファイルとフォルダーをごみ箱へ移します。上書き時はスペースの方針に従って以前のバージョンを保存します。クォータとアップロードサイズの制限も適用されます。MD5 ETag はアップロードした内容を識別し、Content-MD5 と対応する AWS チェックサムヘッダーを検証します。マルチパートの部品は一日以内の一時保存で、未完了アップロードを中止すれば早く解放できます。未完了アップロードはキーごとに 32 件、バケットごとに 128 件、サーバー全体で 512 件までです。各アップロードは 10,000 パートまでです。

対応する操作は ListBuckets（キーに対応するバケットのみ）、HeadBucket、GetBucketLocation、ListObjects/V2、HEAD、範囲と条件付き GET、PUT、同一バケット内の COPY、DELETE と一括削除、マルチパートの開始・パート送信・完了・中止・一覧、署名付き GET/PUT です。署名付き URL の有効期間は最大七日ですが、キーの期限切れや無効化で直ちに停止します。読み取り専用キーは署名付き URL でも PUT できません。

ACL、S3 API によるバケット作成、バケットポリシー、ライフサイクル、Object Lock、S3 バージョニング、カスタムメタデータ、オブジェクトタグ、サーバー側暗号化設定、仮想ホスト形式の URL は提供しません。未対応の操作には NotImplemented を返します。時計はサーバーとのずれを 15 分以内にしてください。署名の失敗にはログインと共通の失敗回数制限を適用します。

FTP 受信フォルダー

FTP 受信フォルダーでは、スキャナーなどの機器が専用の認証情報で一つのフォルダーへアップロードできます。既定では無効です。既存の FTP サーバーをストレージとして追加する機能とは異なり、機器にアカウントやアプリのパスワードを渡す必要はありません。

FTP と明示的 FTPS を有効にする

コントロールパネル › 一般 › アプリとプロトコルでFTP 受信フォルダーを有効にします。ユーザー 1000 が読める PEM 証明書チェーンと秘密鍵をマウントし、Docker Compose サービスに次の設定を加えて再起動してください。

services:
  thirtyfile:
    ports:
      - "2121:2121"
      - "30000-30009:30000-30009"
    volumes:
      - ./ftp-tls:/ftp-tls:ro
    environment:
      THIRTYFILE_FTP_ADDR: 0.0.0.0:2121
      THIRTYFILE_FTP_PASSIVE: 30000-30009
      THIRTYFILE_FTP_PASSIVE_HOST: ftp.files.example.com
      THIRTYFILE_FTP_CERT: /ftp-tls/fullchain.pem
      THIRTYFILE_FTP_KEY: /ftp-tls/privkey.pem

既定の制御アドレスは 0.0.0.0:21 ですが、この例はポート 2121 を使用します。制御ポートとパッシブポートの全範囲を同じ内外ポート番号で公開します。NAT では全ポートをサーバーへ転送し、パッシブホストに公開 DNS 名または IPv4 アドレスを指定します。HTTP リバースプロキシは使いません。明示的 FTPS（AUTH TLS）を使用し、証明書を検証してデータ接続も暗号化（PROT P）してください。暗黙的 FTPS とアクティブモードは提供しません。

公開ネットワークでは暗号化が必須です。信頼できる LAN 上の古い機器に限り、管理者は直接接続されたプライベート／ループバックの接続元からの平文 FTP を許可できます。パスワードとファイルは暗号化されません。待ち受けを信頼できる LAN に限定し、TCP プロキシやインターネットのポート転送経由で平文 FTP を使わないでください。リバースプロキシのヘッダーではこの制約を変更できません。証明書がない場合、明示的に許可されたプライベート接続だけが利用できます。ポートや証明書のエラーはコントロールパネルに表示され、再試行されます。Web サイトの起動は妨げません。無効な FTP はポートを開かず、証明書を読みません。Docker のポートプロキシーはローカルの機器として扱いません。Docker がこの方法で公開ポートを中継すると、すべての接続がコンテナーのゲートウェイから来たように見えるため、平文の FTP は拒否されます。機器を本来のアドレスで識別させるには、コンテナーでホストネットワークを使うか、Docker の userland proxy を無効にしてください。

機器専用の受信フォルダーを作成する

フォルダーを右クリックしてFTP 受信フォルダーを作成…を選ぶか、詳細／プロパティから開きます。管理者はチームフォルダーを公開できます。スペース管理者には FTP ポリシーでの許可が必要です。個人スペース、ゲストアカウント、共有リンクが無効なスペースは公開できません。機器ごとに分かりやすい名前と任意の有効期限を設定し、発行されたユーザー名とパスワードを保存してください。パスワードは一度しか表示されません。

機器にはパッシブモード、サーバーのホスト名と制御ポート、専用のユーザー名／パスワードを設定し、アップロード先を / にします。フォルダーの名前変更や移動後も同じ識別子を追跡します。アップロードは既定で許可されます。一覧取得とダウンロードは別々の設定で、どちらも既定では無効です。SIZE、MDTM、ファイルのメタデータにはダウンロード権限が必要です。機器は削除、移動、名前変更、権限変更、コマンド実行ができません。STOR で保存する機器を使用してください。再開、追記、仮の名前でアップロードしてから名前変更する方式は非対応です。

受信フォルダーのパスワードの更新、再開、デバイスへの一覧表示やダウンロードの許可、期限の延長ができるのは、公開した人か管理者だけです。このフォルダーを管理する他の人は、停止、権限の縮小、削除ができます。アクティビティログの各記録には受信フォルダーの名前が入ります。

コントロールパネル › FTP 受信フォルダーには公開設定、作成者、保存先、権限、有効期限、最終使用時刻が表示されます。本人確認後、設定を編集して停止したり、パスワードを更新したり、認証情報を削除できます。設定変更やパスワード更新は既存の接続も無効にします。新しいパスワードで再接続してください。ファイルは残ります。有効期限、フォルダーのゴミ箱移動、作成者の無効化や公開権限の喪失、スペース共有の無効化でもアクセスが停止します。親フォルダーの公開では、管理者であっても入れ子の制限フォルダーの境界を越えられません。

転送制限と記録

アップロードは確定するまで非公開です。失敗や中止の場合は一時データを削除し、元のファイルを保持します。同名への正常なアップロードでは、スペースのバージョン設定に従って以前の内容が保持されます。スペースの容量制限、読み取り専用、ファイルごとのアップロード上限も適用されます。操作履歴には作成者と受信フォルダーを記録し、認証情報は保存しません。

受信フォルダーごとに同時 5 セッション、サーバー全体で 128 制御接続まで利用できます。サインインは 30 秒以内、制御接続のアイドル時間は 2 分、データ停滞は 30 秒、セッションは最長 1 時間です。一覧は 10,000 項目までなので、機器用フォルダーを小さく保つことを推奨します。誤ったパスワードには Web サイトと共通の接続元制限が適用されます。パッシブデータ接続の接続元は制御接続と同じでなければなりません。FTP bounce／FXP とシンボリックリンクは拒否します。互換機器からのファイル受信向けの機能で、一般的な FTP アカウントではありません。

利用例

サーバーは SSH キーと SFTP スクリプトで毎晩のレポートをアップロードできます。デザイナーは Cyberduck で大きなプロジェクトを転送できます。rclone では rclone config を実行して SFTP を選び、ホスト名とポート、ホストキーの確認、アプリパスワードまたは SSH 秘密キーを設定してください。認証情報をコマンド履歴に残さないようにします。
