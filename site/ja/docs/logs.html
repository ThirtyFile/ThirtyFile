起きたことを確認し、サイトを自分たちに合った外観に整えます。

ログ

コントロールパネル › アクティビティログ を開きます。

ログ記録する内容
アクティビティアップロード、編集、移動、削除、共有、設定の変更
共有リンクへのアクセスリンクを開いた人、パスワードの試行、プレビュー、ダウンロード
サインイン成功と失敗、サインアウト（デバイス からのサインアウトを含む）、パスワード変更、2 段階認証（誤ったコード、回復コードの使用、有効化、無効化、リセット）、アプリパスワードの作成、削除、誤ったシークレットでの試行
エラー利用者が遭遇したエラー。サーバーが完了できなかったリクエストと、Web ページで起きたエラー（ページの表示不能、アップロード、プレビュー、ファイル操作の失敗）

ユーザー、操作、日付で絞り込み、結果を Excel で開ける CSV ファイルに書き出せます。ページで表示している名前、言語、利用者のタイムゾーンを使います。

アクティビティログは、管理者と、スペースのプロパティ（PC）にアクセスするスペースの管理者が使えます。ほかの人は、開けるファイルやフォルダーの最近のアクティビティを 詳細ウィンドウ で確認できます。

ほかの人の個人用スペースに関する記録は、誰が何をいつ行ったかだけを示します。対象のファイルやフォルダー、詳細は表示しません（管理者が見られるもの）。検索と CSV 書き出し、そのスペース内の共有リンクへのアクセスログ、アーカイブファイルでも同様です。

自分のサインイン履歴とサインイン中のデバイスは、誰でもアカウントメニューで確認できます。アカウント を参照してください。

エラー

エラー タブは管理者向けです。発生時刻、遭遇したユーザー（または 未サインイン）、発生元、行っていた操作を記録します。時刻をクリックすると、エラーの種類、リクエストのステータス、リクエスト ID、バージョン、Web ページのエラーのスタックトレースを確認できます。

  • サーバー は、サーバーがエラーを返したリクエストです。データベースや保存先の問題、タイムアウトなどの予期しない失敗は エラー、名前の重複、権限不足、サイズ超過など拒否した変更は 警告 です。重大度 で絞り込めます。
  • Web ページ は、ページから送る記録です。ページが動かなくなった、未処理のスクリプトエラー、アップロード、プレビュー、保存、ファイル操作で表示した失敗が含まれます。
  • サーバーが既に記録したリクエストの失敗をページが報告すると、リクエスト ID で 1 件にまとめ、ページに表示した内容を ページからの報告 に記録します。
  • 10 分以内に同じエラーが再び起きると、新しい記録を増やさず件数を加算します。ユーザーごと、分ごとに報告数を制限し、繰り返し処理でログが埋まらないようにしています。
  • ファイル名やフォルダー名は省略します。引用符内のテキストは "…"（または 「…」）に置き換え、ページは翻訳文ではなくサーバーの英語メッセージを報告します。リクエストは実際に要求したパスではなくルート（PATCH /api/nodes/{id}）で記録します。パスワード、Cookie、共有リンクのトークン、ファイル内容は記録しません。サーバーの失敗の全文は、同じリクエスト ID のサーバーログ（docker logs）にあります。

ログの保存期間

コントロールパネル › ログ設定 で設定します。

  • アクティビティと共有リンクへのアクセスは 180 日、サインインは 365 日保存します。エラーはアクティビティと同じ期間です。
  • 古い記録は圧縮アーカイブに移し、3 年間保存します。同じページからダウンロードできます。アーカイブは 1 行に 1 件の JSON を持ち、ログのコード（upload、bad_password）と 1970 年からの秒数（UTC）を使うため、どの言語でも同じ内容です。
  • 利用者の IP アドレスとブラウザーの記録を無効にできます。
ログには IP アドレスが含まれます。多くの国では個人情報に当たるため、自分たちのプライバシーポリシーに従って保存、削除してください。

ブランド設定

コントロールパネル › ブランド設定 を開きます。

  • 名前とロゴ。必要ならダークモード用のロゴも設定できます。ロゴはブラウザーのタブのアイコンにもなります。
  • ライトモードとダークモードの 色。
  • 外観：ライト、ダーク、各デバイスに合わせる設定と、利用者による変更を許可するかどうか。
  • サインイン画面：背景画像、テキスト、ロック画面を表示するかどうか。
