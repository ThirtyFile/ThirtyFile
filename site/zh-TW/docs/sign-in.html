單一登入

設定身分提供者

  1. 先在控制台 › 一般中設定網站網址。
  2. 開啟控制台 › 單一登入，選擇身分提供者，複製頁面顯示的重新導向位址。
  3. 在身分提供者中註冊 ThirtyFile（參閱下方），貼上該位址。
  4. 將提供者給出的 ID 和 secret 複製到 ThirtyFile，啟用並儲存。

Microsoft Entra ID

Microsoft Entra 管理中心 › App registrations › New registration。選擇「Web」平臺，填寫重新導向位址，再從「Certificates & secrets」新增 client secret。application ID 和 tenant ID 位於「Overview」頁面。

Google

Google Cloud Console › APIs & Services › Credentials › Create credentials › OAuth client ID。選擇「Web application」，在「Authorized redirect URIs」中新增重新導向位址。

GitHub

GitHub › Settings › Developer settings › OAuth Apps › New OAuth App。將重新導向位址填寫為 callback URL，然後產生 client secret。

OpenID Connect（Keycloak、Authentik、Authelia、Zitadel…）

在身分提供者中建立 confidential client（Web 應用程式），設定重新導向位址，並記下 client ID 和 secret。在 ThirtyFile 中填寫 Issuer URL（Keycloak 例如 https://auth.example.com/realms/<realm>）和登入按鈕名稱，例如「公司登入」。儲存時，ThirtyFile 從 <issuer>/.well-known/openid-configuration 讀取設定；issuer 必須使用 https，文件中的 issuer 必須與之相同。

提供者必須回傳使用者的電子郵件地址，並標記為已驗證（email scope 和 claim，以及 email_verified），否則使用者只能自行關聯帳號。允許網域、網域規則、關聯和自動建立帳號與其他提供者相同。

誰可以登入

每個提供者都可以分別設定首次登入規則：

規則處理方式
僅限已關聯帳號只有從帳號選單自行關聯外部帳號的人可登入
以 email 對應既有使用者電子郵件信箱等於某個無密碼、無兩步驟驗證帳號的使用者名稱時可比對，例如同電子郵件信箱單一登入建立的帳號。具有密碼或兩步驟驗證的帳號（例如管理員建立的帳號）不會自動比對，因為提供者登入會繞過這些驗證；擁有者應先用密碼登入一次，再關聯帳號
自動建立帳號允許電子郵件網域中的任何使用者都會獲得新帳號

使用自動建立帳號時，填寫允許的電子郵件網域，例如 example.com，確保只有組織內的人可以存取。

不同網域採用不同設定

電子郵件網域規則可為新帳號設定不同權限、空間容量和群組。例如來自 partner.example 的合作夥伴可獲得較小空間，並禁止分享。

規則也可以決定新帳號是否擁有個人空間（我的檔案），以及使用哪個儲存位置。保留按照系統設定時，採用控制台 › 一般的設定。位置資料夾不可用時，使用者仍可登入；恢復後會在該位置建立「我的檔案」。

自行關聯帳號

所有人都可在帳號選單 › 登入方式中關聯或取消關聯已設定提供者的帳號（Microsoft、Google、GitHub 或 OpenID Connect）。關聯後的帳號可繞過本機密碼登入，因此關聯前需要目前密碼，兩步驟驗證帳號還需驗證碼；無密碼帳號須在登入後 10 分鐘內關聯。每次關聯（包括按電子郵件比對）都會透過應用程式內通知和郵件告知使用者。

設定了允許網域清單時，只有提供者已驗證的、位於該清單網域中的電子郵件信箱才能關聯。關聯帳號只儲存已驗證的電子郵件位址。

單一登入建立的帳號沒有密碼。只有管理員先為其設定密碼後，才能移除最後一個關聯帳號。管理員為使用者設定新密碼時，關聯帳號也會移除；使用者登入後需重新關聯。

目錄登入：LDAP 與 Active Directory

如果你的人員資料放在 Active Directory、OpenLDAP 或 FreeIPA，而且沒有 OpenID 供應商，他們可以用目錄的密碼登入，帳號和群組也會跟著目錄走。開啟控制台 › 目錄登入，先選一種目錄套用範本，然後填入：

  • 位址。ldaps://dc.example.com（從一開始就加密），或 ldap://dc.example.com 並勾選使用 StartTLS。不使用 StartTLS 時連線不加密，只允許連到私人網路上的目錄。如果目錄的憑證由你自己的授權單位簽發，請貼上該授權單位的憑證（PEM）。
  • 服務帳號。可以搜尋目錄的帳號。它的密碼以伺服器的金鑰加密保存，絕不會送回頁面。它只負責找人：人員的密碼是用他們自己的身分登入來檢查。
  • 人員。搜尋基底、含 {username}（代表使用者輸入的內容）的篩選條件，以及存放穩定識別碼（帳號靠它連結，所以目錄中改名不會多出第二個帳號）、使用者名稱、姓名和電子郵件地址的屬性。
  • 群組。從這個人自己的 memberOf 值取得，或搜尋把這個人當成成員的群組（含 {dn} 的篩選條件；在 Active Directory 中，(member:1.2.840.113556.1.4.1941:={dn}) 還會一併處理群組中的群組）。可以要求某個群組的成員才能登入，並選擇這裡的哪些群組要跟著哪些目錄群組走。
目錄人員篩選條件穩定識別碼使用者名稱群組

OpenLDAP(&(objectClass=inetOrgPerson)(uid={username}))entryUUIDuid(&(objectClass=groupOfNames)(member={dn}))
FreeIPA(&(objectClass=posixAccount)(uid={username}))ipaUniqueIDuidmemberOf

測試按鈕會在儲存之前，用輸入的內容試一次：連線（憑證的問題會用文字說明：授權單位不受信任、名稱不符、憑證過期）、服務帳號，然後針對你給的使用者名稱，列出找到的人與各屬性的內容，以及他的群組。遇到第一個出錯的地方就停下，並附上目錄自己的原因。

人員登入時

  • 這裡沒有帳號的使用者名稱會到目錄中查找，並用該人的身分綁定來檢查密碼。密碼絕不會被保存或寫入記錄。手動建立的帳號（第一位管理員、管理員建立的帳號）使用自己的密碼，絕不會送到目錄。
  • 帳號在第一次登入時建立（關閉後只連結已存在的帳號），個人空間比照單一登入，並以目錄的穩定識別碼連結。
  • 登入失敗的次數和密碼一樣受到限制；由於每次猜測都是對目錄的一次綁定，同一個名稱在 15 分鐘內錯誤五次後會被暫停（不論來自哪個位址），以免猜測觸及目錄自己的鎖定。無法連線的目錄會如實告知，不算作密碼錯誤，並在開始與結束時各發出一次管理員警示。如果某人不能使用密碼，他的目錄密碼也不能用。管理員要求時，兩步驟驗證和密碼金鑰仍然適用。SFTP、WebDAV、FTP 和 S3 繼續使用應用程式密碼和金鑰，絕不使用目錄密碼。

人員離開時

每 15 分鐘，以及按下立即同步時，群組會跟著目錄更新；在目錄中已不存在，或在那裡被停用（Active Directory 帳號帶有停用旗標、FreeIPA 或 389 的鎖定）的人，帳號會被停用，登入工作階段也會結束。帳號絕不會被刪除，檔案會保留。人員回到目錄後，帳號會再次啟用；管理員停用的帳號則維持停用。搜尋找不到任何人時不會停用任何人，因為搜尋基底錯誤的可能性更高。屬於跟著目錄走的群組中、由目錄登入的人員，不能在控制台 › 群組中手動更改。

使用者名稱只會作為值放進篩選條件：像 *)(uid=* 這樣的名稱找不到任何人。搜尋結果對同一個名稱有多個項目時會被拒絕，不會跟隨轉介，每次搜尋都有時間與數量上限。

關閉密碼登入

單一登入能運作之後，可以完全不讓人用帳號和密碼登入，讓身分提供者的規則（多重驗證、離職的人）適用於所有人。在 控制台 › 單一登入 › 密碼登入 選擇：

選項結果
所有人和以前一樣：密碼或供應商都可以
僅限管理員登入頁沒有帳號或密碼欄位，只有供應商。管理員用密碼登入的位置是網站的 /sign-in/administrator，沒有任何頁面連到這個網址。供應商故障或設定錯誤時，這是回得來的路
沒有人所有人都透過供應商登入，管理員也一樣，沒有任何頁面提供密碼登入

儲存之前，至少要有一位已啟用的管理員連結到已開啟的供應商，而且你自己必須是其中之一。選擇 沒有人 時，你還必須已經透過供應商登入過一次，讓錯誤的設定現在就被發現。頁面會列出這些管理員。只要密碼登入沒有對所有人開放，最後一位這樣的管理員就不能被停用、刪除、改成標準使用者或解除連結，最後一個供應商也不能關閉：ThirtyFile 會拒絕並說明原因。管理員為某人重設密碼會移除他連結的帳號（見上文），如果因此沒有人能登入，同樣會被拒絕。

受影響的有：用密碼登入、以密碼開始的登入的第二步、用 email 重設密碼（不再提供連結，已寄出的連結也失效）和變更密碼。不受影響的有：應用程式密碼、SFTP 金鑰、S3 金鑰和 FTP 裝置密碼，這些是登入後自己建立的，會一直有效，直到帳號被停用或刪除。已經開啟的登入階段不會中斷。密碼金鑰遵循相同的選擇，因為 ThirtyFile 像密碼一樣保管它們：某人不能使用密碼時，他的密碼金鑰也不能用來登入，頁面也不會提供，所以身分提供者的規則依然適用。

如果供應商無法使用，沒有人能登入，請在伺服器上執行下列指令。立即生效，不需要重新啟動：
docker exec thirtyfile thirtyfile password-sign-in everyone
其他選項是 administrators 和 nobody。密碼登入沒有對所有人開放時，ThirtyFile 啟動時也會在紀錄中發出警告。

包含來賓的 Microsoft 租戶

設定 tenant ID 後，租戶成員可按電子郵件比對。其他組織的來賓也透過你的租戶登入，但電子郵件信箱由其所屬組織提供，而該組織可填寫任意位址。所以來賓電子郵件信箱不用於比對或建立帳號：來賓應使用密碼登入，自行關聯 Microsoft 帳號。

若也需按電子郵件比對來賓，在 ID token 新增可選 claim xms_edov：應用程式註冊中選擇 Token configuration › Add optional claim › ID › xms_edov。Microsoft 會註明來賓電子郵件網域是否屬於其組織，僅比對這些來賓。

透過單一登入建立訪客

在提供者的新帳號預設值選擇建立訪客帳號，或在電子郵件網域規則啟用訪客帳號。符合的網域規則優先於提供者預設值。無論一般個人空間設定為何，訪客都不會建立「我的檔案」。指定群組必須具有符合訪客限制的角色與到期日；不安全的群組成員資格會被拒絕，且不會留下建立到一半的帳號。這些預設值僅適用於新建帳號，不會轉換已連結提供者的現有帳號。請在使用者頁審閱存取權限後轉換現有帳號。
