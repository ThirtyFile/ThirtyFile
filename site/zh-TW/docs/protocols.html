SFTP、S3 與 FTP

程式可透過標準通訊協定操作 ThirtyFile 檔案。管理員啟用後即可使用 SFTP。S3 儲存桶與 FTP 接收資料夾是獨立功能，供應狀態如下說明。

如何選擇

使用 WebDAV 將空間掛載為磁碟；使用 SFTP 透過 WinSCP、FileZilla、Cyberduck、OpenSSH 或 rclone 進行加密傳輸。SFTP 顯示與 WebDAV 相同的目錄樹，遵循相同權限。

SFTP

在控制台 › 一般 › 應用程式與通訊協定開啟允許 SFTP 存取，預設關閉。啟動時使用 THIRTYFILE_SFTP_ADDR 設定連接埠（預設 0.0.0.0:2022）。在 Docker Compose 獨立公開連接埠，SFTP 不經 HTTP 反向代理。

services:
  thirtyfile:
    environment:
      THIRTYFILE_SFTP_ADDR: 0.0.0.0:2022
    ports:
      - "8080:8080"
      - "2022:2022"

將這些項目加入現有 Compose 服務，保留映像與磁碟區。使用 docker compose up -d 重新啟動，僅在必要的網路範圍開放所選 TCP 連接埠。

連線

在用戶端選擇 SFTP，輸入伺服器主機名稱、連接埠 2022、ThirtyFile 使用者名稱與應用程式密碼。此處不接受帳號密碼。唯讀應用程式密碼無法修改檔案，管理員也一樣。第一次信任連線前，請核對控制台顯示的主機金鑰指紋。

sftp -P 2022 amy@files.example.com
# After connecting:
ls
cd "My files"
put report.csv
get report.csv

SSH 公開金鑰

管理員也須開啟允許 SSH 金鑰。在帳號選單 › SFTP 金鑰新增名稱與 SSH 公開金鑰，依要求確認目前密碼與雙因素驗證碼。私密金鑰請保留在自己的裝置。對話框顯示指紋與上次使用時間，移除金鑰後會停止存取，包含現有連線。

sftp -i ~/.ssh/id_ed25519 -P 2022 amy@files.example.com

SFTP 支援範圍

存取權限由 ThirtyFile 角色與分享設定控制。Unix 擁有者變更會被拒絕。權限變更（例如 chmod 600 與 scp -p）會被接受但不改變任何內容。用戶端設定的修改時間（rclone、WinSCP、scp -p）會與檔案內容一起保存並再次顯示，因此依大小與時間同步時只會傳送有變更的檔案；從其他地方變更內容後，會顯示在 ThirtyFile 中變更的時間。S3 回報的也是同一個時間。使用 rclone 時請設定 disable_hashcheck = true，因為伺服器不提供計算遠端檢查碼的 Shell 指令。若無法存取控制台，請向管理員取得預期的主機金鑰指紋。

可列出與下載檔案、上傳、從指定位置續傳、建立資料夾、重新命名、移動及移除項目（送到回收站）。寫入先暫存，關閉檔案時才提交，並套用配額、上傳限制、版本及活動紀錄。斷線時捨棄未完成寫入。接受用戶端時間設定但不儲存。不提供 Shell、指令執行、SSH rsync、轉送或符號連結。每個帳號最多五個連線，每個連線最多 32 個開啟項目，閒置五分鐘後逾時。

首次啟動時，伺服器在資料目錄產生 ed25519 主機金鑰，請一起備份。更換金鑰會改變指紋，用戶端應要求你重新確認。

S3 buckets

將團隊或公司資料夾發布為 bucket。每個 Access Key 只能存取該資料夾，並依建立者目前的權限操作。這與將現有 S3 服務新增為儲存位置不同。

端點設定

在控制台 › 一般 › 應用程式與通訊協定 › S3 啟用 S3，輸入獨立主機名稱，例如 s3.files.example.com，並選擇區域（預設 us-east-1）。S3 預設關閉。代理將此主機名稱轉送至與網站相同的 HTTP 連接埠，不需新增 Docker 連接埠。請保留原始 Host 標頭，它是簽章的一部分。S3 主機名稱需有有效的 HTTPS 憑證與 DNS 紀錄。

將以下指令加入 S3 主機名稱的 HTTPS server 區塊，沿用現有憑證設定。請依磁碟容量與空間配額設定適當的上傳限制。

location / {
    proxy_pass http://thirtyfile:8080;
    proxy_set_header Host $http_host;
    proxy_request_buffering off;
    proxy_buffering off;
    client_max_body_size 0;
}

發布與金鑰

以右鍵點選資料夾並選擇發布為 S3 bucket…，或開啟內容 › S3 buckets。名稱需唯一，並由 3–63 個小寫字母、數字及連字號組成。重新命名或移動資料夾不會改變 bucket 名稱。

管理員可發布團隊或公司資料夾。空間管理者還需有帳號的分享權限，且啟用允許空間管理者發布 buckets。個人空間及可建立分享連結的人設為無人的空間不能發布。資料夾在垃圾桶內、建立者失去管理權或空間停用時，bucket 會停止。還原資料夾或存取權後，已啟用的 bucket 會恢復運作。

發布 bucket 和建立金鑰時，會要求輸入你目前的密碼；有開啟兩步驟驗證時還要輸入驗證碼。金鑰以發布 bucket 的人的身分運作，所以只有發布者或管理員可以建立它的金鑰，或重新啟用已停止的 bucket 或金鑰；其他管理這個資料夾的人可以停止或刪除它們。每項變更都會記錄在活動紀錄中。

建立一個或多個金鑰，填入說明、唯讀或讀寫存取權及選填的到期日。請立即保存 Secret Key，它只顯示一次。金鑰以資料目錄的 secret.key 加密，請依備份指南保存該檔。已啟用的金鑰到期前三天內，建立者會收到存取權即將結束的通知。唯讀空間只能建立唯讀金鑰；建立者的帳號不能更改檔案時，其 Bucket 也只能建立唯讀金鑰，因為讀寫金鑰是以建立者的身分運作。

可單獨停用或刪除金鑰，不影響其他金鑰。控制台 › S3 buckets 列出所有 buckets、建立者、金鑰與上次使用時間。停用 bucket 會阻擋全部金鑰；刪除 bucket 或金鑰不會刪除檔案。Access Keys 不能登入網站、SFTP 或 WebDAV。活動紀錄會標示 bucket 與金鑰說明，不會記錄憑證。

用戶端

在程式中選擇 S3 相容服務：端點 https://s3.files.example.com、區域 us-east-1（或自行設定的區域）、路徑式網址及 bucket 的金鑰。不要啟用虛擬主機式網址、ACL 或伺服器端加密設定。

使用 aws cli 時，請互動設定具名設定檔，避免機密出現在指令歷史。將定址方式設為 path，並在每個指令指定端點。

aws configure --profile thirtyfile
aws configure set s3.addressing_style path --profile thirtyfile
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 ls s3://backups/
aws --profile thirtyfile --endpoint-url https://s3.files.example.com s3 cp report.csv s3://backups/report.csv

使用 rclone 時執行 rclone config，選擇 S3、提供者 Other，互動輸入金鑰，設定端點與區域，啟用 force_path_style，並將 ACL 與伺服器端加密留空。rclone copy 可增加檔案；rclone sync 可能移除目的地檔案。

ThirtyFile 會將 rclone 的 x-amz-meta-mtime 與目前內容版本一起保存，也支援用同名複製更新時間。其他自訂中繼資料（例如 rclone 為大型上傳加上的 MD5）會被接受但不保存。no_system_metadata 無法阻止 rclone 傳送這個時間戳記，請保持關閉。這不會變更 S3 以外的檔案修改時間。

備份與其他用途

使用 restic 時，將備份資料夾發布為 backups，並建立讀寫金鑰。從受保護的憑證儲存區載入 AWS_ACCESS_KEY_ID 與 AWS_SECRET_ACCESS_KEY。Repository 密碼與 S3 金鑰不同，請妥善保管。只在專用的空資料夾內初始化。

restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path init
restic -r s3:https://s3.files.example.com/backups -o s3.region=us-east-1 -o s3.bucket-lookup=path backup ./documents

Duplicati 或 Synology Hyper Backup 可使用 S3 相容目的地，設定相同端點、區域與路徑式網址。請勿在瀏覽器編輯備份 repository 檔案。此 S3 端點是這些工具的目的地，與 ThirtyFile 自身的備份和副本原則不同。

合作夥伴讀取價目表時，可將價目表資料夾發布為 price-lists，並建立 90 天後到期的唯讀金鑰。資料團隊應為每個 rclone 或 aws cli 工作建立獨立金鑰，方便分別停用。

資料夾對應與限制

a/b/c.txt 等 key 對應巢狀資料夾及檔案；PUT 會建立缺少的父資料夾。以 / 結尾的空物件代表資料夾。清單使用 UTF-8 位元組排序、前綴、分隔符號及有上限的分頁。路徑穿越、空白路徑元件、不合法字元或前後空白的名稱會被拒絕。不區分大小寫的空間會拒絕僅大小寫不同的名稱衝突。

DELETE 會將檔案與資料夾移至垃圾桶。覆寫會依空間原則保存舊版本。空間配額與上傳大小限制均適用。MD5 ETag 識別上傳內容，伺服器會驗證 Content-MD5 與支援的 AWS 檢查碼標頭。分段上傳的片段在暫存區保留最多一天，可中止未完成上傳以提早釋放。每個金鑰最多 32 個、每個 bucket 最多 128 個待完成上傳（全伺服器 512 個），每次最多 10,000 個片段。

支援操作包含 ListBuckets（僅該金鑰的 bucket）、HeadBucket、GetBucketLocation、ListObjects/V2、HEAD、範圍與條件式 GET、PUT、同 bucket 內的 COPY、DELETE 與批次刪除、分段建立／上傳／完成／中止／列出，以及預先簽署 GET/PUT。PUT 與完成分段上傳支援 If-None-Match: *（僅在該 key 尚無物件時寫入，Terraform 的鎖定檔需要此功能）與 If-Match（僅覆蓋該 ETag 的內容）；儲存物件時會再次檢查條件，因此兩個同時寫入者只有一個會成功。刪除資料夾 key（以 / 結尾）時，只有空資料夾會被刪除，如同 S3 只移除資料夾標記：其中的物件會保留。要求超過 1,000 個 key、分段或上傳時，和 AWS 一樣回傳 1,000 個。預先簽署網址最多有效七天，金鑰到期或停用後立即失效。唯讀金鑰即使使用預先簽署網址也不能 PUT。沒有另外要求時，下載是附件（Content-Disposition: attachment、X-Content-Type-Options: nosniff）。預先簽署網址可以像 S3 一樣用 response-* 參數要求其他的顯示方式、檔名、類型或快取設定；這些參數屬於簽章的一部分，所以只有持有金鑰的人能要求。

不提供 ACL、透過 S3 建立 bucket、bucket 原則、生命週期、Object Lock、S3 版本 API、物件標籤、伺服器端加密設定或虛擬主機式網址。不支援的操作回應 NotImplemented。時鐘需與伺服器相差 15 分鐘內；錯誤簽章與登入共用失敗限制。

FTP 接收資料夾

FTP 接收資料夾讓掃描器等裝置使用專用憑證上傳到單一資料夾。此功能預設關閉，與將既有 FTP 伺服器新增為儲存位置不同。裝置不使用你的帳號密碼或應用程式密碼。

啟用 FTP 與明確 FTPS

在控制台 › 一般 › 應用程式與通訊協定啟用FTP 接收資料夾。掛載使用者 1000 可讀取的 PEM 憑證鏈與私密金鑰。在 Docker Compose 服務加入下列選項後重新啟動：

services:
  thirtyfile:
    ports:
      - "2121:2121"
      - "30000-30009:30000-30009"
    volumes:
      - ./ftp-tls:/ftp-tls:ro
    environment:
      THIRTYFILE_FTP_ADDR: 0.0.0.0:2121
      THIRTYFILE_FTP_PASSIVE: 30000-30009
      THIRTYFILE_FTP_PASSIVE_HOST: ftp.files.example.com
      THIRTYFILE_FTP_CERT: /ftp-tls/fullchain.pem
      THIRTYFILE_FTP_KEY: /ftp-tls/privkey.pem

預設控制位址為 0.0.0.0:21，此範例使用 2121。控制連接埠與全部被動模式連接埠都要公開，內外連接埠號碼相同。NAT 須轉送這些連接埠至伺服器，並將被動模式主機設為公開 DNS 名稱或 IPv4 位址。FTP 不經 HTTP 反向代理。請使用明確 FTPS（AUTH TLS）、驗證伺服器憑證，並加密資料連線（PROT P）。不提供隱含 FTPS 或主動模式。

公開網路連線必須加密。只有可信區域網路的舊裝置，才由管理員允許直接連接的私人或本機位址使用未加密 FTP；密碼與檔案會以明文傳送。請將此監聽服務限制在可信區域網路，不要透過 TCP 代理或網際網路連接埠轉送使用明文 FTP。反向代理標頭不會改變這項政策。未設定憑證時，只接受明確允許的私人網路連線。控制台顯示連接埠或憑證錯誤並自動重試，不會阻止網站啟動。FTP 關閉時不開放連接埠，也不讀取憑證。Docker 的連接埠代理永遠不會被當成區網裝置：Docker 以這種方式轉送公開的連接埠時，所有連線看起來都來自容器的閘道，因此會拒絕純文字 FTP。要讓裝置以自己的位址被辨識，請讓容器使用主機網路，或關閉 Docker 的 userland proxy。

為裝置建立專用接收資料夾

對資料夾按右鍵選擇建立 FTP 接收資料夾…，或從詳細資料／內容開啟。管理員可以發布團隊資料夾，空間管理者需經 FTP 政策允許。個人空間、訪客帳號與關閉分享連結的空間不能發布。為每個裝置設定便於辨識的名稱與選用的到期日。請立即保存產生的裝置使用者名稱及密碼；密碼只顯示一次。

裝置設定使用被動模式、伺服器主機名稱及控制連接埠、裝置憑證，上傳目錄為 /。資料夾重新命名或移動後，發布仍跟隨其識別碼。預設允許上傳；列出內容與下載是兩個獨立選項，預設皆關閉，僅啟用裝置需要的權限。SIZE、MDTM 與檔案中繼資料需要下載權限。裝置不能刪除、移動、重新命名、變更權限或執行命令。請使用以 STOR 儲存的裝置；不支援續傳、附加上傳或「先上傳暫存名稱再重新命名」流程。預設情況下，上傳會取代同名檔案並保留先前版本，適合重複儲存相同名稱的攝影機。掃描器請關閉取代同名檔案，名稱已被使用的新檔案會加上編號，現有檔案不會改變。

只有發布接收資料夾的人或管理員可以輪替它的密碼、重新啟用它、允許設備列出或下載檔案，或延長它的到期日；其他管理這個資料夾的人可以停止、縮小權限或刪除它。活動紀錄的每一筆都會寫出接收資料夾的名稱。

控制台 › FTP 接收資料夾列出所有發布、建立者、目的資料夾、權限、到期日與上次使用時間。確認身分後可編輯停用、輪替密碼或刪除憑證。政策變更或密碼輪替也會使既有連線失效；輪替後使用新密碼重新連線，檔案仍保留。到期、資料夾進入垃圾桶、建立者被停用或失去發布權限、空間分享關閉時，存取也會停止。上層發布不能穿越巢狀限制資料夾的邊界，管理員也一樣。

傳輸限制與紀錄

上傳內容在提交前保持私密；失敗或取消會清除暫存並保留原檔。同名檔案上傳成功時，依空間版本政策保留先前版本。空間配額、唯讀空間與單檔上傳限制仍適用。活動紀錄標示建立者與接收資料夾，不記錄憑證。

每個接收資料夾最多同時 5 個連線，伺服器最多 128 個控制連線。登入限時 30 秒，控制連線閒置 2 分鐘、資料停滯 30 秒後結束，連線最長 1 小時。清單最多 10,000 個項目，建議裝置使用較小的接收資料夾。錯誤密碼共用網站的來源位址登入限制。被動資料連線的來源必須與控制連線相同，拒絕 FTP bounce／FXP 與符號連結。此功能供相容裝置收件使用，不是通用 FTP 帳號。

使用案例

伺服器可使用 SSH 金鑰與 SFTP 腳本上傳每晚報表；設計師可使用 Cyberduck 傳輸大型專案。使用 rclone 時執行 rclone config，選擇 SFTP 並設定主機名稱與連接埠，核對主機金鑰，使用應用程式密碼或 SSH 私密金鑰；避免將憑證寫入指令歷史。
